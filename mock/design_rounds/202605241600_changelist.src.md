## Comparison to deprecated changelist

This CL was revised in place (still active, not yet locked) once code-path scoping surfaced two design tensions the original draft did not resolve.

First, `viola_config::ViolaConfig<'a, const MAX_PLUGINS: usize>` carries a lifetime parameter, which conflicts with the `Resource<T>` `T: 'static` bound. Original draft claimed `Resource<ViolaConfig>` directly. Revised: Slice 1 introduces a local `ViolaConfigOpaque` placeholder in `viola-core::wus`. Slice 2 (`LoadConfig` body) wires the real owned-form bridge. Consequence: no `viola-config` dep is added in Slice 1; that addition shifts to Slice 2.

Second, the original draft proposed per-WU `*CtxUnimplementedStub` types mirroring the `AdaptCtxUnimplementedStub` precedent at `~/Dev/clause-dev/hilavitkutin/mock/crates/hilavitkutin-providers/src/adapt_wu.rs:63`. Revised: one shared `WuCtxStub<'frame>` in `viola-core::wus::stub` covers every WU's `type Ctx<'frame>` in Slice 1. Six identical stub types is duplication; one shared type is the smaller surface. Body slices replace each WU's Ctx with the engine-generated Ctx independently.

Third, `Workspace.path` / `Workspace.surface` / `CiState.is_ci` / `CiState.agent` / `AgentKind` field-and-enum claims moved to Slice 2. Slice 1 ships `Workspace` and `CiState` as zero-sized resource markers so the AccessSet bounds compile; field shape is body-slice scope.
