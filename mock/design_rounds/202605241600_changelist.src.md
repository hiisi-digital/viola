## `mock/crates/viola-core/src/resources.rs` (NEW)

Two new POD value types that wrap into `Resource<T>` at scheduler build time. The third resource the topic calls out (`RunSurface`) is the existing enum already re-exported from `viola_plugin_abi`; no new struct is introduced for it. All fields use arvo or hilavitkutin primitives; no heap.

- `Workspace`: workspace root path (`hilavitkutin_str::Str`, interned at scheduler-build time) plus a `surface: viola_plugin_abi::RunSurface` field classifying how the run was invoked. The `RunSurface` enum already covers `Cli`, `Hook`, `Ci`, `Lsp`, `Test`, `Other`; the `Dap` case folds into `Other` for this slice and gets a dedicated variant only when a dap-driven body slice needs to distinguish it. `Workspace.surface` is a snapshot of the invocation context; the separate `Resource<RunSurface>` is what drives diagnostic egress routing (they can diverge when an Lsp-initiated run egresses through a Hook).
- `CiState`: `arvo::Bool` flag for "running under CI" plus an `AgentKind` enum (`None`, `Human`, `Bot`, `Unknown`) classifying the invoking actor.

Each struct gains `Default`. Neither is `Copy` (`Str` carries a generation field that the `Copy` contract would mislabel); both are `Clone` for scheduler-builder ergonomics.

Body: `fn execute<'frame>(&self, _ctx: &Self::Ctx<'frame>) { unimplemented!("Slice 2 implements LoadConfig") }`.

Pairs with `impl BuilderInput for LoadConfig { type Init = Self; type Dispatch = UnitDispatch<Self>; }` per the trait's `on_unimplemented` directive in `hilavitkutin-api/src/work_unit.rs`.
