# Design tensions

## Tension 1: DiagnosticSink shape

The Slice 1 stub declared `Resource<DiagnosticSink>` in Write but DiagnosticSink is a ZST. Slice 7a flips DiagnosticSink to a non-ZST placeholder so consumers can extend without churn; Slice 7b flips to the actual carrier.

What does DiagnosticSink ultimately carry? Three sub-options:

- **Path A: trait-driven**. DiagnosticSink wraps a writer trait (custom `EmitWriter` in viola-core). EmitDiagnostics calls methods on the trait; viola-cli provides the concrete impl. Cleanly separates concerns but adds a generic parameter.
- **Path B: tagged enum**. DiagnosticSink is a `#[repr(C)]` enum with variants `Stderr`, `Stdout`, `Json(BytesEmitter)`, etc. Simple but couples the WU to all output formats.
- **Path C: stage-and-defer**. DiagnosticSink is a Cell-wrapped `[u8; CAP]` arena into which EmitDiagnostics writes serialised bytes; viola-cli reads after `scheduler.run()` and dispatches to the real I/O. Adds a copy + cap-bounded staging.

Slice 7b will pick Path A: trait-driven via a workspace-local `EmitWriter` trait. The trait surface lives in viola-core; viola-cli provides the concrete impl. The Slice 7a shape is the non-ZST placeholder; Slice 7b flips to `pub struct DiagnosticSink<W: EmitWriter> { writer: UnsafeCell<W> }` with private fields (no `pub` exposure on transient placeholder slots between 7a and 7b).

## Tension 2: EmitWriter trait surface

Slice 7b ships a minimal `EmitWriter` trait. Open question to resolve in Slice 7b: return type. Two paths:

- **Return unit**. `fn write_str(&mut self, s: &str)`. Simpler; viola-cli's impl handles syscall failures internally per its discretion (panic, log, silent drop).
- **Return `notko::Outcome<()>`**. Surfaces I/O failure to the caller. EmitDiagnostics decides whether to abort or continue on a failed write.

This is a real open design call, not collapsed to unit-return in 7a. Slice 7b's topic+DOC CL pick a path with rationale.

## Tension 3: sorting strategy under Str::default placeholders

ABI doc §10 names the canonical diagnostic sort: `(path, start_line, start_col, plugin_id, rule_id)`. The pre-#254 `viola_core::aggregate::cmp_diag` implements this for the FFI `Diagnostic`. Host-side `WuDiagnostic` has different field types: `severity`, `source`, `message: Str`, `range`. Path, plugin_id, rule_id fields do not exist on WuDiagnostic yet (deferred to the Slice 6a host-side LintFinding carrier BACKLOG entry).

Slice 7b sorts by `(source, severity, range.start_line, range.start_col, original_slot_index)` as the host-side approximation. The trailing tiebreaker on original slot index gives deterministic output across runs against the same input. The host-side approximation is a documented deviation from the ABI canonical sort; the canonical restoration waits on the host-shim long-lived interner (Slice 2b BACKLOG) shipping the LintFinding carrier with interned path/plugin_id/rule_id fields.

## Tension 4: surface choice (CLI / JSON / LSP)

Slice 7b hardcodes human-readable. JSON / LSP defer to a future slice that introduces `Resource<RunSurface>` (already on Slice 6a BACKLOG).

## Tension 5: disjoint per-L row-range gap handling

Slice 6b RunLint writes to disjoint slots `[L * MAX_DIAGS_PER_LINT, (L + 1) * MAX_DIAGS_PER_LINT)`. Unused slots in the per-L range stay at their initial value.

Slice 7b picks Path B: per-L populated count via `Resource<DiagnosticCounts>`: `[arvo::USize; MAX_LINTS]`. RunLint's Write set extends to include this Resource (a load-bearing AccessSet change to the already-locked Slice 6b RunLint body). EmitDiagnostics reads to iterate per-L only up to the populated count.

**The RunLint AccessSet extension is a load-bearing change.** Slice 9 parallel fan-out verification (the existing Slice 6a BACKLOG entry) needs to re-check the COMMUTATIVE flag against the extended Write set. Adding a Resource Write to RunLint widens the parallel-fan-out commutativity surface; Slice 9 audits whether `Resource<DiagnosticCounts>` writes at distinct slots `L` across the parallel RunLint cohort still commute. Slice 7b's CL ratifies this; Slice 9's audit confirms.
