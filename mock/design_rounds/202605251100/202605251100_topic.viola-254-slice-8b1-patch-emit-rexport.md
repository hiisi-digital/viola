# Why this round exists

The originally-scoped Slice 8b proposed shipping the full viola-cli
scheduler-build chain in one PR. Implementation surfaced a cross-repo compile
blocker: adding `hilavitkutin` (the engine crate) to viola-cli's `Cargo.toml`
triggered a transitive compile failure on `arvo-spectral`, with
`Csr::row_col_indices` and `Csr::row_values` reported as missing methods.
Investigation showed the methods exist on arvo's HEAD; the failure was a
viola-mock-workspace `[patch]` configuration gap, not an arvo bug. The patch
overrides six arvo crates to local paths
(`arvo, arvo-bits, arvo-bitmask, arvo-refit, arvo-storage, arvo-bits-contracts`)
but not the remaining ten
(`arvo-comb, arvo-graph, arvo-hash, arvo-mask-contracts, arvo-numeric-contracts, arvo-sparse, arvo-spectral, arvo-strategy, arvo-tensor, arvo-transparent`).
When hilavitkutin pulls `arvo-spectral`, cargo resolves it from git while
`arvo-sparse` (its dep) sees a mix of git-fetched and path-patched arvo types,
producing the misleading "method not found" error from a type-identity mismatch.

Slice 8b.1 fixes the patch gap and lands the other engine-independent pieces.
Slice 8b.2 builds the scheduler-build chain on top in a subsequent round,
confident the patch resolution is sound.

# Settled design decisions (from the discarded Slice 8b topic memo)

The two open design questions from Slice 8a's BACKLOG were settled in the
discarded Slice 8b topic memo and stay settled for 8b.1 / 8b.2 alike:

- **ExtensionHost re-export disambiguation**: drop the re-export entirely.
  Consumers split: viola-cli imports `hilavitkutin_extensions::ExtensionHost`
  directly when it needs the substrate type for plugin-loading; uses
  `viola_core::resources::ExtensionHost` for the scheduler-builder Resource
  (Slice 8b.2). Other sibling re-exports (`ProviderId`, `Extension`,
  `ExtensionMeta`, `ExtensionRequirement`, etc) stay because they are
  non-colliding plugin-loading surfaces.

- **EmitWriter concrete impl shape**: `pub struct StderrEmitter;` ZST with
  `libc::write(2, ptr, len)` retry loop, panic-on-syscall-failure (routes via
  the existing panic_handler to libc::abort), no-op `flush` (unbuffered).
  Pre-1.0; the trait can switch to buffered later without API change.

- Drop `ExtensionHost` from the `pub use hilavitkutin_extensions::{...}` block.
  Add a one-line comment explaining the Slice 8b.1 settlement and pointing
  consumers at the substrate-direct import.

In `viola-cli/`:

- New file `src/emit.rs` with `pub struct StderrEmitter` ZST and
  `impl viola_core::wus::EmitWriter for StderrEmitter`. Three methods:
  `write_str(s: &str)` (calls helper on `s.as_bytes()`),
  `write_bytes(bytes: &[u8])` (calls helper directly), `flush(&mut self)`
  (no-op). Internal helper `write_all_to_stderr(bytes: &[u8])` loops
  `libc::write(2, ptr, len)` until the buffer drains; panics on `-1` errno or
  zero-progress retry exhaustion.
- `src/main.rs` adds `mod emit;` decl. Keeps the Slice 8a
  `unimplemented!("Slice 8b ships viola-cli scheduler rewire ...")` stub in the
  lint path (Slice 8b.2 replaces it). The `StderrEmitter` is
  `#[allow(dead_code)]` until Slice 8b.2 wires it; the type-level proof (it
  impls `EmitWriter` for a concrete type) is the load-bearing test for 8b.1.
