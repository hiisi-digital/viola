# Design tensions for the RunLint body

The body lifts to FFI via `viola_plugin_abi::LintEvaluateVtable::evaluate`:

```
unsafe extern "C" fn(
    host_ctx: *mut c_void,
    nam: *const NamPayload,
    lint_config_bytes: *const u8,
    lint_config_len: arvo::USize,
    out_batch: *mut DiagnosticBatch,
) -> AbiStatus
```

The lint receives the scope-wide NAM (from `Column<Nam>` slot zero per Slice 5b) plus per-lint config bytes, returns a `DiagnosticBatch` (pointer + length) of `Diagnostic` records. Determinism per ABI doc §10: the host sorts on path, start_line, start_col, plugin_id, rule_id after the call; lints emit in any order.

## Tension 1: const-L slot to plugin mapping

`RunLint<const L: usize>` is monomorphised per L by the scheduler at plan time. Each `RunLint<L>` impl needs to know which lint plugin corresponds to slot L. Three options:

- **Path A: Resource<LintSlots>**. a Resource carrying `[arvo::Cap; MAX_LINTS]` (each slot holds the ExtensionHost host_idx of the lint plugin at that slot, or a sentinel for "no plugin at this slot"). LoadPlugins (Slice 3) extended to populate this at runtime, OR the host shim pre-populates it from the parsed ViolaCfg lint list at scheduler-builder time. RunLint<L> body reads `Resource<LintSlots>` and `slots[L]` gives the host_idx.
- **Path B: per-slot Column<PluginEntry> walk**. RunLint<L> walks Column<PluginEntry> filtering for entries with the lint role bit set, counts to the Lth match. O(L * MAX_PLUGINS) but simple; no new Resource.
- **Path C: extend Column<PluginEntry> with slot info**. add a `lint_slot: arvo::Cap` field to PluginEntry that LoadPlugins populates. RunLint<L> walks PluginEntry looking for `entry.lint_slot == L`. Conflates concerns; PluginEntry would carry runner-only state for non-lint entries.

Slice 6b will pick Path A. Rationale: clean separation (LintSlots is a derived view; PluginEntry stays the canonical record); host-shim pre-population fits the established pattern (DiscoveredFilePaths, FileEntryBuffer). The LintSlots populator can live in LoadPlugins (Slice 3 already walks PluginEntry; extending its Write set to include `Resource<LintSlots>` is a small change) OR in a new tiny WU `IndexLints` that runs between LoadPlugins and the first RunLint<L>. Slice 6b ratifies which.

## Tension 2: lint config bytes per slot

Each `RunLint<L>` invocation passes `lint_config_bytes` for that specific lint. ViolaCfg carries `[LintConfigBlock; MAX_RULES]` (or similar). RunLint<L> needs to project the right block's bytes to FFI.

Two paths:
- **Path A: Resource<LintConfigBuffer>**. a host-shim-built Resource carrying a fixed-cap array of `BytesRef` (one per slot), with each `BytesRef` pointing into the ViolaCfg arena's bytes. Slice 6b body reads `slots[L]` and passes that BytesRef's `data` + `len` to the FFI.
- **Path B: read from ViolaCfg at WU time**. RunLint<L> takes `Resource<ViolaCfg>` in Read, calls a `lint_config_at(L)` accessor that returns the bytes. Adds ViolaCfg to RunLint's AccessSet (every L slot reads the same Resource; scheduler may not parallelise the cohort if it sees shared Reads).

Slice 6b will pick Path A. Rationale: Resources designed for parallel fan-out should have minimal shared dependencies; the LintConfigBuffer indirection lets each RunLint<L> read its own slot without forcing serialisation on ViolaCfg. The host shim builds LintConfigBuffer once at scheduler-builder time from the parsed ViolaCfg blocks; the body never touches ViolaCfg.

## Tension 3: COMMUTATIVE = Bool::TRUE

The `WorkUnit` trait carries `const COMMUTATIVE: Bool = Bool::FALSE` defaulting to non-commutative. The scoping memo names `COMMUTATIVE = Bool::TRUE` as the load-bearing claim for parallel fan-out: when set, the scheduler dispatches `RunLint<0>..RunLint<MAX_LINTS-1>` in parallel because their `Column<WuDiagnostic>` writes commute under the COMMUTATIVE flag.

This is the ONE source-touching CHANGE in Slice 6a: set `const COMMUTATIVE: Bool = arvo::Bool::TRUE` on the `WorkUnit` impl for `RunLint<L>`. Slice 9 audits whether the landed hilavitkutin dispatch codegen actually honours this flag with reduce-style parallel fan-out (vs serialising).

## Tension 4: Column<WuDiagnostic> write semantics under parallel fan-out

When `RunLint<0>..RunLint<MAX_LINTS-1>` run in parallel, each writes to `Column<WuDiagnostic>`. Slice 5b RunRunner used the singleton-row convention (slot zero only); that doesn't compose with parallel fan-out because every RunLint<L> would write to slot zero and races would occur.

Two paths:
- **Path A: per-L row range**. each RunLint<L> writes to `Column<WuDiagnostic>` starting at slot `L * MAX_DIAGS_PER_LINT` for up to that count. Disjoint slot ranges by construction; no race. Cap the per-lint output at compile time.
- **Path B: per-L append-style**. each RunLint<L> claims an atomic counter slot before each write. Requires hilavitkutin-api atomic-counter support and a shared Resource for the counter.

Slice 6b will pick Path A. Rationale: matches the COMMUTATIVE flag's intent (every slot is disjoint; writes commute trivially); no atomic-counter dependency; cap-bounded. `MAX_DIAGS_PER_LINT` const lives alongside MAX_LINTS.

## Tension 5: host-side Diagnostic carrier vs WuDiagnostic

The FFI returns `DiagnosticBatch { entries: *const Diagnostic, len: arvo::USize }`. The Slice 1 stub writes to `Column<WuDiagnostic>` (host-side carrier with Str-handle fields). Mapping FFI `Diagnostic` (BytesRef fields, plugin-owned) to `WuDiagnostic` (Str-handle fields, host-interned) requires interning each BytesRef into the host's long-lived interner. The Slice 2b host-shim long-lived interner BACKLOG entry blocks this.

Slice 6b options:
- **Path A: defer interning**. RunLint body writes `WuDiagnostic` records with `Str::default()` for each Str field (matches the Slice 2b/3/4/5b deferrals on the interner). Diagnostic gets a `source: WuDiagnosticSource::RunLint`, severity passes through, range passes through. Other fields empty until the interner lands.
- **Path B: introduce a host-side Diagnostic carrier mirroring FFI Diagnostic**. `pub struct LintFinding { plugin_id: Str, rule_id: Str, severity, message: Str, path: Str, range, suggestion: Str, ... }`. Replaces WuDiagnostic at the lint output layer or extends Column<WuDiagnostic>'s element type. Larger design surface.

Slice 6b will pick Path A. Rationale: WuDiagnostic is the existing host-side carrier per Slice 2b; reuse it; defer the rich-field projection until the interner lands. The Slice 1 declared `Write = Cons<Column<WuDiagnostic>, Empty>` stands.
