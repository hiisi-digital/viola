# What Slice 2b ships

The Slice 2a SRC CL committed `LoadConfig::execute` as `unimplemented!("Slice 2b implements LoadConfig")`. Slice 2b replaces that body with the real parse path. Three pieces interlock:

First, `ConfigArena<const N: usize>` gains real `ArenaInterner` methods. `arena_intern` appends bytes to the fixed-cap buffer at the current cursor, returns the offset as the 28-bit id. `arena_resolve` reads the bytes back via offset plus length. Cursor management uses `Cell<arvo::USize>` for `&self`-callable interior mutability. The 28-bit id space caps the offset addressable into the buffer; for `ARENA_BYTES = 8192` the buffer fills long before the id space does, so the cap that matters in practice is `N`, not `2^28`.

Second, `LoadConfig::execute` reads `Resource<Workspace>`, `Resource<RunSurface>`, and `Resource<ConfigBytes>`; calls `viola_config::parse` on the bytes; projects the borrowed `ViolaConfig<'a, N>` into the owned `ViolaCfg` using the bundled `ConfigArena` to intern each borrowed slice; writes the result into `Resource<ViolaCfg>`. On parse failure, writes a `Diagnostic` to `Column<Diagnostic>` and returns early.

Third, the placeholder `Diagnostic` in `viola-core::wus` flips from ZST to field-bearing. **It is renamed in the same step.** `viola_plugin_abi::Diagnostic` already ships at the FFI boundary as a `#[repr(C)]` plugin-owned carrier (`plugin_id`, `rule_id`, `severity`, `message: BytesRef`, `path`, `range`, `suggestion`); two types named `Diagnostic` in the same workspace would re-tokenise as a reinvention per `use-the-stack-not-reinvent.md`. The DOC CL picks the rename (working name: `WuDiagnostic` for the host-side `Column<T>` element type; the DOC CL phase commits the final name). The minimum fields the parse path needs:

```rust
pub struct WuDiagnostic {
    pub severity: viola_plugin_abi::DiagnosticSeverity,
    pub source: WuDiagnosticSource,
    pub message: hilavitkutin_str::Str,
    pub range: notko::Maybe<viola_plugin_abi::SourceRange>,
}

pub enum WuDiagnosticSource {
    ConfigParse,
    // future variants per producer slice
}
```

Two divergences from `viola_plugin_abi::Diagnostic`: this type is the in-process `Column<T>` element used by host-internal WUs; it never crosses the FFI boundary. The ABI type is the plugin-owned carrier with `BytesRef` strings; this host-side type interns through `hilavitkutin_str::Str`, matching the rest of the host surface (`Workspace.path`, `ViolaCfg`'s strings). `EmitDiagnostics` (Slice 7) projects this host-side type into whatever output target (stderr / JSON / LSP) needs at egress.

`viola_plugin_abi::SourceRange` (not `SourceLocation`; the natural field for a parse error is a range) is the cross-type bridge: both ABI and host diagnostics reference the same source-range shape.

# Decisions to ratify in DOC CL

The recommendations below frame each axis with the alternatives. The DOC CL author picks or refines; the framing is not load-bearing on the recommendation.

## ConfigArena byte layout

Three sub-questions on the arena's internal shape:

- **Entry indexing**: offsets table (offset, length pairs keyed by id) separately from the bytes, or interleaved length-prefixed entries in the byte buffer. Offsets table doubles static memory cost (each entry is two `arvo::USize`, around 16 bytes on 64-bit) but makes lookup `O(1)`. Interleaved entries are tight on memory but make lookup scan from the start. For a config arena holding a few dozen strings, the offsets table is the recommended tradeoff: fast resolution matters more than the table's static cost. Alternative remains open if the DOC CL author observes a different cost balance.
- **Dedup**: deduplicate identical strings at intern time, or skip. The `StringInterner` wrapper already checks the const linker section first; runtime-runtime dedup needs a hash index on the offsets table. Recommended: no dedup for a one-shot parse arena. Alternative remains open.
- **`Cell` vs `UnsafeCell`**: `ArenaInterner::arena_intern` takes `&self`, so interior mutability is required. `core::cell::Cell<arvo::USize>` works for a `Copy`-able cursor; the byte buffer itself needs `UnsafeCell`. The DOC CL commits the layout; the SRC CL phase implements it.

## Diagnostic field shape

Three sub-questions on the `Diagnostic` ZST flip:

- **Source enum**: how many variants does `DiagnosticSource` ship in Slice 2b? Minimum is one (`ConfigParse`) because that is the only producer Slice 2b lands. Adding `RunnerFailure` / `LintFailure` / `IoError` etc. for future slices is documentation theatre per the SHAME framing; each variant lands in the slice that first uses it.
- **Message carrier**: `hilavitkutin_str::Str` (a 4-byte handle) requires interning at the producer site. Alternative: fixed-cap `[u8; MAX_DIAG_MESSAGE_LEN]` plus a `Cap` length. The `Str` shape is consistent with the rest of the workspace (`Workspace.path`, `ViolaCfg`'s interned strings) but introduces an arena dependency. The byte-array shape is heavier per `Diagnostic` but self-contained. Slice 2b recommendation: `Str` with host-shim arena, matching `Workspace.path`'s pattern.
- **Source location**: do we carry a `SourceLocation` (line, column) from `viola_plugin_abi`? Slice 2b's parse-failure case has no line/column data from `viola_config::parse` (the parser returns a `ConfigError` enum without span info). The field shape ships an `Option`-like `Maybe<viola_plugin_abi::SourceLocation>`; the parse-fail emit-path sets it to `Maybe::Isnt`. Future producers fill it.

## Polish items from PR #25 review

PR #25 reviewer flagged six non-blocking polish items. Slice 2b's DOC CL decides which to fold in.

- **Const-generic name collision** in `ViolaConfigOwned`. The struct's const parameters are named the same as the workspace pub consts (`MAX_PLUGINS`, etc.); inside the struct body the names resolve to the generic, but the shadowing is a footgun. Two paths: rename the const parameters with a suffix (e.g. `MAX_PLUGINS_CAP`), or drop the generics entirely since the type is only ever instantiated at workspace defaults via `ViolaCfg`. The DOC CL chooses one; Slice 2b's SRC CL lands the rename or the de-generification.
- **`ConfigBytes` shape**: `[u8; CONFIG_MAX_BYTES] + Cap` vs `BytesRef`-shaped carrier. The reviewer's note pointed at `use-the-stack-not-reinvent.md`'s canonical `LintConfig = BytesRef` example. That example is a *consumer-of-plugin-bytes* type (FFI carrier with `(*const u8, len)` shape over plugin-owned memory). `ConfigBytes` is a *host-owned* fixed-cap buffer that the host shim writes once and `LoadConfig` reads. The two shapes do not interchange: `BytesRef` does not own its bytes, the host needs to. Slice 2b stays with the array shape; the DOC CL records this distinction so a future reader does not mis-read it as a `use-the-stack-not-reinvent` violation.
- **`arvo::Bool` Default upstream**: `arvo::Bool` ships `ConstDefault` but not `core::Default`. The `CiState` manual `Default` impl exists because of this gap. Fix is one line in arvo (a bridge from `ConstDefault` to `Default`). Out of scope for Slice 2b; tracked separately as an arvo-side follow-up.
- **`Workspace.path` host-shim docstring**: add a one-line note on the `path` field naming the host-shim interner contract. Trivial; Slice 2b folds in.
- **Workspace-dep trim**: `arvo-refit`, `arvo-storage`, `arvo-bits-contracts` entered viola's `[workspace.dependencies]` but are not directly named in any crate. The `[patch.*]` entries are necessary for local-path-override; the workspace-deps lines are over-broad. Slice 2b's source phase drops the unused workspace-deps lines.
- **AccessSet-shape test**: add a test in `viola-core/tests/load_config.rs` that asserts `LoadConfig::Read` and `Write` are the expected cons-list shapes at the type level. Slice 2b lands this alongside the body fixture.

# Body sketch

Illustrative pseudocode for the DOC CL phase to refine. The real Ctx accessor surface lives at `hilavitkutin-api::context`; this sketch uses placeholder names.

```rust
fn execute<'frame>(&self, ctx: &Self::Ctx<'frame>) {
    let bytes_resource = ctx.read::<Resource<ConfigBytes>>();
    let bytes = &bytes_resource.bytes[..bytes_resource.len.get()];

    let borrowed = match viola_config::parse::<MAX_PLUGINS>(bytes) {
        notko::Outcome::Just(cfg) => cfg,
        notko::Outcome::Aint(err) => {
            let diag = Diagnostic::from_config_error(err);
            ctx.column_push::<Diagnostic>(diag);
            return;
        }
    };

    let owned = ViolaCfg::from_borrowed(&borrowed);
    ctx.write::<Resource<ViolaCfg>>(owned);
}
```

The DOC CL phase commits the real accessor method names, the `Diagnostic::from_config_error` projection logic, and the `ViolaCfg::from_borrowed` constructor signature.
