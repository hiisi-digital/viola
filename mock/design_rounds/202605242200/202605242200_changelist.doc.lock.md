# Decisions committed

## 1. `WuDiagnostic` is the host-side Column element type name

The Slice 2a ZST placeholder named `Diagnostic` collides with
`viola_plugin_abi::Diagnostic` (the FFI `#[repr(C)]` carrier at
`mock/crates/viola-plugin-abi/src/diagnostic.rs:67`). Per
`.claude/rules/use-the-stack-not-reinvent.md`, two types with the same name in
the same workspace re-tokenise as reinvention. Slice 2b renames the host-side
type to `WuDiagnostic`. The Slice 1 `Column<Diagnostic>` AccessSet entries in
`LoadConfig`, `EmitDiagnostics`, and any other producer become
`Column<WuDiagnostic>` mechanically.

The two types stay distinct: `viola_plugin_abi::Diagnostic` carries
`BytesRef`-shaped strings for plugin-owned memory crossing the FFI boundary;
`WuDiagnostic` carries `hilavitkutin_str::Str` handles matching the rest of the
host surface. Slice 7's `EmitDiagnostics` body is the projection point between
the two at the egress boundary.

## 2. `WuDiagnostic` field shape

```rust
pub struct WuDiagnostic {
    pub severity: viola_plugin_abi::DiagnosticSeverity,
    pub source: WuDiagnosticSource,
    pub message: hilavitkutin_str::Str,
    pub range: notko::Maybe<viola_plugin_abi::SourceRange>,
}

pub enum WuDiagnosticSource {
    /// Parse failure on `Resource<ConfigBytes>` (Slice 2b producer).
    ConfigParse,
    /// Plugin dlopen, descriptor verification, or ABI gate failure (Slice 3 producer).
    PluginLoad,
    /// Filesystem walk error or include/exclude pattern mismatch (Slice 4 producer).
    FileWalk,
    /// Runner WU body failure (Slice 5 producer).
    RunRunner,
    /// Lint WU body failure (Slice 6 producer).
    RunLint,
    /// `EmitDiagnostics` sink-side egress failure (Slice 7 producer).
    Emit,
}
```

`severity` reuses the ABI enum directly: stderr / JSON / LSP egress all care
about the severity level, and there is one canonical scale. `source` is a
closed-vocabulary host-side enum classifying which WU produced the diagnostic.
The full variant set ships in Slice 2b per the closed-enum-as-spec pattern
(`vocabulary.md` cites `Phase` as the canonical precedent). Slice 2b's
`LoadConfig::execute` only constructs `ConfigParse` values; later slices
construct their respective variants. Future producers may extend the enum;
closed-vocabulary additions require a design round. `message` is interned
through the host shim's long-lived interner, matching the `Workspace.path`
pattern. `range` is `Maybe::Isnt` for parse failures (the parser does not carry
line / column data); future producers may set it.

## 3. `ConfigArena` byte layout

Three sub-decisions:

- **Offsets table separate from byte buffer**. The arena holds an array of
  `(offset, length)` pairs keyed by id, plus the byte buffer itself. `O(1)`
  lookup via id-as-index. Costs roughly `MAX_ENTRIES * 2 * sizeof(USize)` of
  static overhead; for a config-arena workload the table is a small fraction of
  the total. The alternative (interleaved length-prefixed entries) saves the
  table but makes `arena_resolve` scan from the buffer start; not worth the cost
  for a workload with frequent resolves.
- **No dedup**. The `StringInterner` wrapper already short-circuits identical
  const-section entries; runtime-runtime dedup would need a hash index that is
  not worth the cost for a one-shot parse arena.
- **`Cell<arvo::USize>` for cursor, `UnsafeCell<[u8; N]>` for byte buffer**.
  `ArenaInterner::arena_intern` takes `&self` so both need interior mutability.
  `Cell` works for the `Copy`-able cursor; the byte buffer needs `UnsafeCell`
  for `&mut [u8]` access through `&self`.

The `ConfigArena<N>` type stays generic over the buffer size; `MAX_ENTRIES` is a
sibling const-generic introduced in this CL.
`pub const ARENA_MAX_ENTRIES: usize = 256` per workspace default; the bare
`usize` type matches the sibling `MAX_PLUGINS` / `MAX_GATES` / `MAX_RULES`
consts (bare `usize` is required for `ConstParamTy` const-generic instantiation
per the workspace-default pattern Slice 2a established).

`Sync` for `ConfigArena<N>`: `UnsafeCell<[u8; N]>` is `!Sync` by default. The
hilavitkutin scheduler ships compile-time probes on `ResourcePtr<T: Sync>`
(`hilavitkutin/.../tests/resource_send_sync.rs`), and `Resource<ConfigArena<N>>`
(transitively embedded in `Resource<ViolaCfg>`) must satisfy those bounds.
`ConfigArena<N>` ships an explicit
`unsafe impl<const N: usize> Sync for ConfigArena<N>` with a SAFETY note:
`LoadConfig` is the sole producer (declared in its `Write` set; the scheduler's
AccessSet contract serialises writes on a Resource), subsequent WUs hold `Read`
access only and do not call `arena_intern` (interior mutability through `&self`
is a contract held by the writer, not exercised by readers). The `unsafe impl`
is sound under the AccessSet serialisation guarantee. SRC CL ships the SAFETY
note inline.

## 4. `LoadConfig::execute` body shape

Reads `Resource<Workspace>`, `Resource<RunSurface>`, `Resource<ConfigBytes>`.
Calls `viola_config::parse::<MAX_PLUGINS>` on the bytes. Projects the borrowed
`ViolaConfig` into `ViolaCfg` via the bundled arena. On parse failure, writes a
`WuDiagnostic` to `Column<WuDiagnostic>` and returns early. On success, writes
`Resource<ViolaCfg>`.

The body uses the canonical `hilavitkutin-api::context` accessor surface:
`HasResourceProvider::resources()` for `&self`-borrow Resource reads,
`HasColumnWriter::writer()` for Column appends. The exact method calls land in
the SRC CL phase against the actual trait surface.

## 5. Polish items folded into Slice 2b SRC phase

- **Const-generic name collision in `ViolaConfigOwned`**: rename the const
  parameters with a `_CAP` suffix (`MAX_PLUGINS_CAP`, `MAX_GATES_CAP`, etc.) so
  the struct body's parameter references do not shadow the module-scope consts.
  The `ViolaCfg` alias still instantiates with the workspace consts; the rename
  is internal to the struct definition.
- **`ConfigBytes` shape**: stays as `[u8; CONFIG_MAX_BYTES] + Cap`. The DOC CL
  records why (host-owned vs plugin-owned distinction); no source change.
- **`arvo::Bool` Default**: tracked under task #428
  (`arvo: ship Debug on UFixed/IFixed/Bits/USize/Bool/FastFloat/StrictFloat numerics`)
  which the arvo follow-up covers. Out of Slice 2b's scope.
- **`Workspace.path` docstring**: add a one-line note on the field naming the
  host-shim interner contract.
- **Workspace-dep trim**: deferred to a separate `chore:` PR. Bundling the trim
  with Slice 2b body would make a revert of Slice 2b drag an unrelated cleanup;
  the trim is small enough to ship on its own.
- **AccessSet-shape test**: add a compile-time test in
  `viola-core/tests/load_config.rs` asserting `LoadConfig::Read` and `Write` are
  the expected cons-list shapes.

## 6. `WuDiagnostic` SHAME removal

Slice 2a's `viola-config/SHAME.md.tmpl` doesn't carry a `Diagnostic` entry (the
type is in `viola-core/src/wus/mod.rs`, not `viola-config`). The Slice 2 docs
round (PR #27) added DESIGN sections for the three substantive types but did not
document the ZST placeholders. Once Slice 2b lands `WuDiagnostic` with fields, a
follow-up DOC round adds the `### WuDiagnostic` section to
`viola-core/DESIGN.md.tmpl`. SHAME-vs-DESIGN management is the same shape
pattern Slice 2a followed.
