# What Slice 3 ships

The Slice 1 stub at `viola-core/src/wus/load_plugins.rs` declares:

```rust
type Read = Cons<Resource<ViolaCfg>, Empty>;
type Write = Cons<Column<PluginEntry>, Empty>;
```

with an `unimplemented!()` body. Slice 3 replaces the body with the real plugin
load path. Five pieces interlock.

First, `viola_config::PluginEntryOwned` (the ZST placeholder inside
`ViolaConfigOwned.plugins[..plugins_len]`) flips to fields-bearing with two
`Str` handles: the plugin's display name and its filesystem path. Both intern
through the bundled `ConfigArena` during `populate_from_borrowed` projection.

Second, `viola-core::wus::PluginEntry` (the ZST placeholder element of
`Column<PluginEntry>`) flips to fields-bearing with the loaded plugin's runtime
state: display name `Str`, role mask (using `arvo_bitmask::Mask64` per
`use-the-stack-not-reinvent.md`'s BAD/INSTEAD pair for `RoleSet`), ABI version
(matched against the contract version declared in `viola-plugin-abi`), and a
handle to the loaded extension (shape pending DOC CL decision; see below).

Third, `ViolaConfigOwned::populate_from_borrowed` gains its first real
projection arm: the plugins arm. Walks `borrowed.plugins[..plugin_len]`, calls
`self.arena.arena_intern` on each `&[u8]` path, writes the resulting `Str`
handle into each `self.plugins[i]` slot, advances `self.plugins_len`. The other
arms (gates, rules, partial_rules) stay no-op; their producer slices will
revisit. The Slice 2b BACKLOG entry for
`populate_from_borrowed owned-record fill-in` partially clears.

Fourth, `LoadPlugins::execute` body: read `Resource<ViolaCfg>` via
`HasResourceProvider<Self::Read>::resource::<ViolaCfg>()`, walk the projected
`cfg.plugins[..cfg.plugins_len]`, for each entry call
`hilavitkutin_linking::Library::open(&path)` and verify the
`__hilavitkutin_extension_descriptor` symbol per `hilavitkutin-extensions`'
contract. On success, push a `PluginEntry` to `Column<PluginEntry>`. On failure,
write a `WuDiagnostic { source: PluginLoad, ... }` to `Column<WuDiagnostic>` and
continue with remaining plugins (do not fail the WU; per-plugin failures egress
through the diagnostic channel, not WU abort).

Fifth, `LoadPlugins`'s AccessSet extends: Write set grows `Column<WuDiagnostic>`
alongside the existing `Column<PluginEntry>`. Same pattern as `LoadConfig` Slice
2b.

# Decisions to ratify in DOC CL

The recommendations below frame each axis with the alternatives. The DOC CL
author picks or refines; the framing is not load-bearing on the recommendation.

## Plugin handle shape inside `PluginEntry`

The single hardest question. Three sub-paths considered. A constraint discovery
during topic drafting closes Path A: `Column<T>` requires
`ColumnValue = Copy + 'static`, and `hilavitkutin_linking::Library` has a `Drop`
impl for RAII dlopen cleanup (`hilavitkutin-linking/src/lib.rs:105`). `Library`
cannot be `Copy`, so `Column<PluginEntry>` cannot carry it by value. This forces
the recommendation to Path B.

- **Path A: `PluginEntry` carries `Library` by value.** Rejected. `Library` is
  not `Copy` (has `Drop`); `Column<T>` requires `Copy + 'static` element type.
  Would either need to make `Library` `Copy` (loses RAII) or carry an opaque
  handle and manage Drop manually (loses the safety the `Library` wrapper
  provides). Both losses are larger than Path B's setup cost.
- **Path B: `Resource<ExtensionHost>` holds the `Library` instances;
  `Column<PluginEntry>` records carry an `arvo::Cap<MAX_PLUGINS>` index into the
  host.** Matches the scoping memo's "writes `Resource<ExtensionHost>`" framing.
  `ExtensionHost` is a singleton fixed-cap store of `Library` values; Drops fire
  on Resource teardown at scheduler-run end. `PluginEntry` records stay `Copy`
  because they carry only an index plus the descriptor-projected metadata. The
  Read set of every WU that calls plugin entry points (`RunRunner`,
  `RunLint<L>`) adds `Resource<ExtensionHost>` alongside `Column<PluginEntry>`;
  the index resolves to a `&Library` via `ExtensionHost::library_at(cap)`.
- **Path C: `PluginEntry` carries `Maybe<&'static Library>` and the `Library`
  instances live in a host-shim long-lived store.** Long-lived borrows in
  `Column<T>` element type. Rejects per
  `hilavitkutin-workunit-mental-model.md`'s
  lifetime-parameters-in-consumer-public-APIs smell.

Recommendation: Path B. The Copy constraint on Column elements rules out Path A.
Path B's `Resource<ExtensionHost>` needs an `unsafe impl Sync` story mirroring
`ConfigArena`'s (single-writer per AccessSet, scheduler serialises), but the
SAFETY note pattern is now well-established. The Slice 3 AccessSet grows:
`Write = Cons<Resource<ExtensionHost>, Cons<Column<PluginEntry>, Cons<Column<WuDiagnostic>, Empty>>>`.
Subsequent WUs read `Resource<ExtensionHost>` plus their Column index for handle
resolution.

## Plugin lifetime

Per-run (dropped at WU completion) versus per-session (long-lived across
multiple scheduler runs).

The hilavitkutin engine is one-shot per `scheduler.run()` call. Plugins
reasonably live for that run. `Library` shipping a `Drop` impl that closes the
dlopen handle on Column drop is the natural shape. If a future viola integration
runs the scheduler multiple times in one process, Path A's Column<PluginEntry>
reloads plugins each run; if that proves costly, a follow-up moves to Path B
with a per-session store.

Recommendation: per-run for Slice 3. Document the per-session pivot as a future
BACKLOG entry.

## Schedule: `Always` vs `On<PlanStage>`

The scoping memo argues for `On<PlanStage>` because plugins load once per
process. But the current `Always` schedule (no special trigger) runs at every
scheduler pass. With one-shot viola, the difference vanishes (one pass = one
plugin load). `On<PlanStage>` requires a `Virtual<PlanStage>` marker;
introducing it for Slice 3 adds scope.

Recommendation: stay `Always` for Slice 3. The scoping memo's `On<PlanStage>`
framing assumed multi-pass viola; one-shot viola does not need the distinction.

## `PluginEntry` field shape

The recommended fields:

| Field         | Type                                  | Why                                                                                                                                                                                                      |
| ------------- | ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`        | `hilavitkutin_str::Str`               | Display name, interned at load via the host-shim long-lived interner                                                                                                                                     |
| `roles`       | `arvo_bitmask::Mask64`                | Role set (runner / grammar / lint). `use-the-stack-not-reinvent.md` BAD/INSTEAD pair                                                                                                                     |
| `abi_version` | `hilavitkutin_extensions::AbiVersion` | Matches the descriptor's `abi_version` shape directly. The constant lives at `hilavitkutin-extensions/src/descriptor.rs:28` as `AbiVersion(pub u32)`; matched against `HOST_ABI_VERSION = AbiVersion(2)` |
| `host_idx`    | `arvo::Cap<MAX_PLUGINS>`              | Index into `Resource<ExtensionHost>` for handle resolution by downstream WUs                                                                                                                             |

The DOC CL ratifies. `PluginEntry` is `Copy` (none of the field types ship
Drop); the `Library` itself lives in `Resource<ExtensionHost>` per Path B.
`AbiVersion(u32)` is the documented descriptor type; no narrowing happens here.
Workspace `MAX_PLUGINS = 16` caps both the Column and the `ExtensionHost`.

## `PluginEntryOwned` field shape

The recommended fields:

| Field  | Type                    | Why                                                            |
| ------ | ----------------------- | -------------------------------------------------------------- |
| `name` | `hilavitkutin_str::Str` | Parser-side display name; intern via the bundled `ConfigArena` |
| `path` | `hilavitkutin_str::Str` | Filesystem path for `Library::open`                            |

Two `Str` handles. Both intern during `populate_from_borrowed` from the parser's
`&[u8]` slices. The Slice 2b DOC CL committed the no-op stub; this round fills
the plugins arm.

## Plugin-load failure handling

Per-plugin failures egress through `Column<WuDiagnostic>` (the Slice 2b
channel). The DOC CL ratifies which `WuDiagnosticSource` variant the failures
use (`PluginLoad` per the Slice 2b closed enum). Failure modes to cover:

- Path resolution failure: file does not exist, permission denied.
- dlopen failure: malformed shared object, missing exported symbol.
- Descriptor verification failure: bad magic number, ABI version mismatch,
  malformed provider table.
- Role mask malformedness: descriptor declares no roles (every plugin must
  declare at least one).

Recommendation: one `WuDiagnostic` per failed plugin, message body interned via
the host-shim long-lived interner (the Slice 2b deferred work; same TODO as the
parse-failure message). Surviving plugins still populate the Column. The WU does
not return early on first failure.

**Column-index semantics for `Column<PluginEntry>`**: records land only on the
`Ok` arm of load. Failed loads write a `WuDiagnostic` and skip the PluginEntry
write. The Column length therefore tracks "successfully loaded plugins" and does
not match `cfg.plugins_len` when failures occur. Downstream WUs that index
plugins by Column position must NOT assume positional parity with the config's
plugin manifest; they walk the loaded set independently. RunLint<L>'s
const-generic `L` indexes into the loaded set, not the manifest, so the L-th
loaded plugin may correspond to a different manifest position. The DOC CL
ratifies this semantic.

# Body sketch

Illustrative pseudocode for the DOC CL phase to refine. The real Ctx accessor
surface lives at `hilavitkutin-api::context`; this sketch uses the same
fully-qualified shape as `LoadConfig`.

```rust
fn execute<'frame>(&self, ctx: &Self::Ctx<'frame>) {
    type R = <LoadPlugins as WorkUnit>::Read;
    type W = <LoadPlugins as WorkUnit>::Write;
    type Stub = <WuCtxStub<'static> as HasResourceProvider<R>>::Provider;

    let cfg: &ViolaCfg = <Stub as ResourceProviderApi<R>>::resource::<ViolaCfg>(
        <WuCtxStub<'frame> as HasResourceProvider<R>>::resources(ctx),
    );

    let n: usize = *cfg.plugins_len.0;
    for i in 0..n {
        let path: &str = cfg.arena_resolve(cfg.plugins[i].path);
        match hilavitkutin_linking::Library::open(path) {
            Outcome::Ok(lib) => {
                match verify_descriptor(&lib) {
                    Outcome::Ok((name, roles, abi_version)) => {
                        let entry = PluginEntry { name, roles, abi_version, lib };
                        // ColumnWriterApi::write at index i (parallel to record-index-per-load).
                        write_entry(ctx, USize(i), entry);
                    }
                    Outcome::Err(_e) => emit_diag(ctx, WuDiagnosticSource::PluginLoad),
                }
            }
            Outcome::Err(_e) => emit_diag(ctx, WuDiagnosticSource::PluginLoad),
        }
    }
}
```

The DOC CL phase commits the real `verify_descriptor` signature, the `emit_diag`
helper, the `arena_resolve` accessor on `ViolaConfigOwned` (the public surface;
today `arena` is private), and the exact column-write index semantics (one
record per attempted load including failures, versus one record per successful
load only).
