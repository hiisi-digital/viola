## CHANGE: new type `ExtensionHost` in viola-core

File: `mock/design_rounds/202605250000_changelist.doc.md` (this CL)
Verification: the type shape is specified here; source lands in src CL.

Singleton store of loaded extension handles. Fixed-cap array sized at
`MAX_PLUGINS = 16`. Two fields.
`libs: core::cell::UnsafeCell<[core::mem::MaybeUninit<hilavitkutin_linking::Library>; MAX_PLUGINS]>`
for the per-plugin handle slots. `MaybeUninit` because partially-populated
arrays in no_std cannot zero-init Drop types.
`loaded_len: core::cell::Cell<arvo::USize>` tracks the count of initialised
slots.

Plus an `unsafe impl Sync for ExtensionHost` with SAFETY note mirroring
`ConfigArena`'s. `LoadPlugins` is the sole producer (declared in its `Write`
set; scheduler's AccessSet contract serialises that producer slot); downstream
WUs (`RunRunner`, `RunLint<L>`) hold `Read` access only and resolve handles via
`&self`-borrow accessors.

Drop semantics: `ExtensionHost` ships a `Drop` impl that walks
`libs[..loaded_len]` and calls `MaybeUninit::assume_init_drop` on each slot. The
Resource lifetime is per-scheduler-run; the dlopen handles drop at run end.

Public surface. `pub const fn new() -> Self` constructs an empty host.
`pub fn library_at(&self, idx: arvo::Cap) -> &hilavitkutin_linking::Library`
reads slot `idx` (note: `arvo::Cap` is the plain newtype `Cap(USize)` at
`arvo-storage/src/platform.rs:75`; it is not const-generic). SAFETY: the
function internally bounds-checks `idx < loaded_len` and panics (debug) or
returns undefined behaviour (release) on violation. The bounds check is
mandatory inside the body, not trusted from any co-write invariant alone,
because the function dereferences a `MaybeUninit<Library>` slot and reading an
uninitialised slot is UB.
`pub(crate) unsafe fn push(&self, lib: hilavitkutin_linking::Library) -> arvo::Cap`
appends one library and returns its slot index; SAFETY: caller asserts
`loaded_len < MAX_PLUGINS`; bounds-checked at runtime; returns the 0-based
index. Single-writer per AccessSet.

The unsafe-impl-Sync SAFETY note explicitly names four invariants. First,
`LoadPlugins` is the only WU writing this Resource. Second, the scheduler
serialises Write access to a Resource at AccessSet dispatch time. Third,
downstream WUs (`RunRunner`, `RunLint<L>`) declare `Resource<ExtensionHost>` in
their Read sets; the scheduler's phase-separation analysis proves no concurrent
dispatch between `LoadPlugins` and the readers in the same scheduler run.
Fourth, the interior mutability through `&self` is single-threaded per the
scheduler's per-WU dispatch model.

DESIGN.md.tmpl section for `### ExtensionHost` lands in the follow-up docs round
per the Slice 2b precedent (PR #29's decision 7 deferred Slice 2b doc sections
to round 202605242350). Documenting the type here keeps the DOC CL focused on
decisions; the rendered docs surface gains the section after source ships.

## CHANGE: `PluginEntry` flips from ZST to fields-bearing

File: `mock/design_rounds/202605250000_changelist.doc.md` (this CL)
Verification: the field shape is specified here; source lands in src CL.

Four fields per the topic table. `name: hilavitkutin_str::Str`.
`roles: arvo_bitmask::Mask64`.
`abi_version: hilavitkutin_extensions::AbiVersion`. `host_idx: arvo::Cap`.
`arvo::Cap` is the plain `Cap(USize)` newtype (not const-generic); the
MAX_PLUGINS bound applies via the host's fixed-cap array, not via a `Cap<N>`
const parameter.

Derives `Copy, Clone, Debug, PartialEq, Eq` to satisfy
`ColumnValue = Copy + 'static`. All field types are `Copy`: `Str` is a 4-byte
handle, `Mask64` is `Bits<64, Hot>`, `AbiVersion(u32)` is a wrapper, `Cap` wraps
`USize` which wraps `usize`. No Drop.

`host_idx` is the bridge to `Resource<ExtensionHost>`: callers resolve the
underlying `&Library` via `host.library_at(entry.host_idx)`.

`### PluginEntry` DESIGN section lands in the follow-up docs round alongside
`### ExtensionHost`. Same deferral pattern.

## CHANGE: `populate_from_borrowed` plugins arm shipped

File: `mock/design_rounds/202605250000_changelist.doc.md` (this CL)
Verification: the body shape is specified here; source lands in src CL.

Slice 2b shipped `populate_from_borrowed` as a no-op stub. Slice 3 fills the
plugins arm. The body walks `borrowed.plugins[..borrowed.plugin_len.0]`, calls
`self.arena.arena_intern` on each `&[u8]` path (treating the bytes as utf-8;
viola-config's parser emits utf-8 path slices), wraps the returned 28-bit id
into a `Str` via `hilavitkutin_str::Str::__runtime(Bits<28, Hot>::from_raw(id))`
(the public constructor at `hilavitkutin-str/src/handle.rs:51` for
runtime-interned handles), writes
`PluginEntryOwned { name: Str::default(), path: <the runtime-interned Str> }`
into `self.plugins[i]`, and advances `self.plugins_len` to
`arvo::Cap(arvo::USize(n))`.

The `name` slot stays `Str::default()` until the host-shim long-lived interner
is registered at scheduler-builder time (Slice 2b BACKLOG carryover). Display
names come from the loaded plugin's descriptor, not the parser; the host-shim
interner is the right home for them.

Note the public surface: `Str` exposes `__make` (const-origin) and `__runtime`
(runtime-interned) constructors keyed by `Bits<28, Hot>`. The `__runtime`
constructor is the right one for arena-interned values because the bit-31 origin
marker distinguishes runtime from const-origin handles for downstream consumers
that read `is_runtime()`.

Gates / rules / partial_rules arms stay no-op for Slice 3; their producer body
slices revisit.

## CHANGE: new public accessor `ViolaConfigOwned::plugin_path`

File: `mock/design_rounds/202605250000_changelist.doc.md` (this CL)
Verification: the accessor signature is specified here; source lands in src CL.

`LoadPlugins::execute` needs to read interned plugin paths back as bytes to feed
`Library::load`. The current `ConfigArena::arena_resolve` is private to the
crate; `LoadPlugins` lives in viola-core, which cannot reach it.

The new public accessor: `pub fn plugin_path(&self, i: arvo::Cap) -> &str` on
`ViolaConfigOwned`. Hides the arena from consumers. Walks
`self.plugins[i.0.0].path`, calls the inner `arena.arena_resolve(path.id())`,
returns the `&str` view. The accessor is `&self`-receiver; the lifetime of the
returned `&str` is `&self`-bound (the standard arena contract). The src CL also
commits a small null-termination helper at the LoadPlugins body site that copies
the `&str` bytes into a fixed-cap stack buffer with a trailing NUL byte, because
`Library::load(path: &[u8])` at `hilavitkutin-linking/src/lib.rs:50` requires a
null-terminated byte sequence per the docstring.

A sibling `plugin_name` accessor lands in the same shape when display names
become non-default. For Slice 3, `plugin_path` is the only accessor the body
needs.

## CHANGE: `LoadPlugins::execute` body shape committed

File: `mock/design_rounds/202605250000_changelist.doc.md` (this CL)
Verification: the body shape is specified here; source lands in src CL.

Concrete body uses the same fully-qualified-path resolution as Slice 2b's
LoadConfig. Type aliases for `R` and `W` (the Read and Write AccessSets), then
`<Stub as ResourceProviderApi<R>>::resource::<ViolaCfg>` for the config read and
`<Stub as ResourceProviderApi<W>>::resource::<ExtensionHost>` for the host
write-through-interior-mutability. The body walks `cfg.plugins_len` indexes,
calls `cfg.plugin_path(i)` (returns `&str`), copies the bytes into a fixed-cap
stack buffer with a trailing NUL byte (the null-termination helper), dlopens via
`hilavitkutin_linking::Library::load(null_terminated_bytes)` (the real API at
`hilavitkutin-linking/src/lib.rs:50` takes `&[u8]` null-terminated per the
docstring). On `Outcome::Ok` calls `verify_descriptor(&lib)`, on its
`Outcome::Ok` calls `host.push(lib)` (unsafe-wrapped per the SAFETY contract),
constructs a `PluginEntry { name, roles, abi_version, host_idx }` and writes to
`Column<PluginEntry>`. On either `Outcome::Err`, emits a
`WuDiagnostic { source: WuDiagnosticSource::PluginLoad, ... }` to
`Column<WuDiagnostic>` and continues with the next plugin.

The body is single-threaded per WU dispatch; the Resource and Column writes
interleave safely because the AccessSet contract serialises the entire WU's
Write set.

`verify_descriptor` is the loaded-plugin contract verification step. Signature:
`fn verify_descriptor(lib: &Library) -> Outcome<(Str, Mask64, AbiVersion), VerifyError>`.
Looks up `hilavitkutin_extensions::DESCRIPTOR_SYMBOL` from the library, reads
the `ExtensionDescriptor`, checks `abi_version == HOST_ABI_VERSION`, derives the
`Mask64` role set from the descriptor's provider table, interns the display name
(via host-shim interner once that lands; `Str::default()` placeholder until
then). The src CL phase commits the `VerifyError` variants and the
descriptor-to-Mask64 projection.

## CHANGE: Column-index semantic ratified

File: `mock/design_rounds/202605250000_changelist.doc.md` (this CL)
Verification: the semantic is specified here; downstream slices reference it.

Records land in `Column<PluginEntry>` only on the `Ok` arm of load AND the `Ok`
arm of `verify_descriptor`. Failed loads write a
`WuDiagnostic { source: PluginLoad }` to `Column<WuDiagnostic>` and skip the
`PluginEntry` write.

The Column length therefore tracks "successfully loaded plugins" and does not
match `cfg.plugins_len` when failures occur. Downstream WUs that index by Column
position walk the loaded set independently. `RunLint<L>`'s const-generic `L`
indexes into the loaded set, not the config manifest; the L-th loaded plugin may
correspond to a different manifest position.

The column-write index for the i-th attempt: one record appended per successful
load at index = current Column length at write time. The body tracks the next
write-index locally (a `loaded_count: usize` counter increments on each
successful push). The local-counter == column-length invariant holds by
construction because: (1) the writer-side Column<T> starts empty at the
beginning of each scheduler run; (2) `LoadPlugins::execute` is the only WU
writing this Column in this round; (3) the counter increments exactly when a
`write` call succeeds; (4) no other WU pushes to the Column between
`LoadPlugins::execute` calls in the same scheduler run. This sidesteps the
`hilavitkutin-api` gap where the writer side has no `Column::len` accessor
today; the gap is tracked as a BACKLOG entry under viola-core.
