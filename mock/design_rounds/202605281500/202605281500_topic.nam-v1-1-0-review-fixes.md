# Topic: NAM v1.1.0 post-review hardening

**Date:** 2026-05-28
**Phase:** TOPIC
**Scope:** Address two pre-merge review findings on the NAM v1.1.0 surface in `viola-plugin-abi/src/nam.rs`: a stale module-head doc and a missing whole-multiple guard in the slice accessors. Source-only; touches `nam.rs`.

**Source TOPIC:** rounds 202605281300 / 202605281400 (NAM v1.1.0), on this branch.

# Why this round exists

A local pre-merge review of the NAM v1.1.0 change surfaced two findings worth fixing before merge:

1. The `nam.rs` module-head doc still titles the schema `# NAM v1.0.0 wire schema` and states the `nam_file_entries` accessor returns `None` when the version is not v1.0.0. After the gate widened to accept any v1.x payload, that header is stale and contradicts the updated function and struct docs.
2. `nam_file_nodes` (and the pre-existing `nam_file_entries`) compute the record count by truncating integer division of a byte length, with no guard that the byte length is a whole multiple of the record size and no statement of the pointer-alignment precondition. A malformed carrier would silently drop a trailing partial record, and a misaligned pointer would make the `from_raw_parts` call unsound.

# What lands

- Rewrite the `nam.rs` module-head schema section to describe the v1.x line, the major-version gate, and the v1.1.0 node array.
- Add a `debug_assert!` that the carrier byte length is a whole multiple of the record size in both `nam_file_entries` and `nam_file_nodes`, and name the contiguous-and-aligned precondition in each `# Safety` / SAFETY comment.
