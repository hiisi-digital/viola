# Why this round exists

The mockspace bucket-2 cdylib lints walk the NAM v1.1.0 flat `NamNode` array. Two families need node kinds not in #616's 19-kind table:

- **ast-node-position** matches `call_expression` and `field_expression` (plus item kinds already present).
- **ast-type-position** inspects types at struct-field / fn-param / fn-return / type-alias / enum-variant / associated-type positions. A cdylib finds the type at a position by collecting the type-leaf nodes under a position-context node, so it needs the position-context kinds (`field_declaration`, `parameter`, `enum_variant`, `associated_type`) and the type-leaf kinds (`type_identifier`, `primitive_type`). Compound type wrappers (reference, generic, ...) are not needed: the cdylib collects leaf descendants.

These kinds also belong in the producer's vocabulary (the rust-native runner, #220), so defining them now is foundational, like #616 shipping the schema ahead of its producer.
