**Round:** 202605282500 **Phase:** DOC (locked) **Topic:**
`202605282500_topic.nam-node-kinds-v1-2.md` **Scope:**
`viola-plugin-abi/DESIGN.md.tmpl` updates for the v1.2.0 kind vocabulary. The
wire layout is unchanged from v1.1.0; this is a vocabulary (kind-id) extension

## D1: v1.2.0 is a vocabulary extension, not a layout change

`NamVersion::V1_2_0` carries the same `NamPayload` / `NamFileEntry` / `NamNode`
layout as v1.1.0. The only change is the `node_kind` id vocabulary growing with
expression and type-position ids. Because kinds are append-only and a
`NamNode.kind` is an opaque `arvo::USize`, a v1.1.0 consumer still reads a
v1.2.0 payload (it treats ids 20+ as unknown numbers). The bump signals only
that the producer MAY emit ids 20 and above. The `NamVersion` and `node_kind`
DESIGN sections are updated to record the new version and the eight new kinds.

## D2: which kinds, and why these

The kinds are chosen to make the mockspace bucket-2 lints portable without
linking tree-sitter:

- node-position: CALL_EXPRESSION, FIELD_EXPRESSION.
- type-position contexts: FIELD_DECLARATION, PARAMETER, ENUM_VARIANT,
  ASSOCIATED_TYPE (FnReturn / TypeAliasBody reuse the existing FUNCTION_ITEM /
  TYPE_ITEM containers).
- type leaves: TYPE_IDENTIFIER, PRIMITIVE_TYPE.

Compound type wrappers (reference, generic, scoped, ...) are deliberately
omitted: a lint inspecting a position's type collects the type-leaf descendants
of the position node, so only the leaf kinds are needed to match a forbidden
type by name.
