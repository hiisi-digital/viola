## CHANGE: BACKLOG entry `ExtensionHost re-export disambiguation` ADDED to viola-core/BACKLOG.md.tmpl
File: `mock/crates/viola-core/BACKLOG.md.tmpl`
Verification: `grep -q "ExtensionHost re-export disambiguation" mock/crates/viola-core/BACKLOG.md.tmpl`.

viola-core currently has two `ExtensionHost` types: `viola_core::ExtensionHost` (re-exported from `hilavitkutin_extensions`) and `viola_core::resources::ExtensionHost` (the Slice 3 Resource version). Both coexist via path disambiguation. Slice 8b settles the collision: either drop the re-export (consumers import the substrate type directly from `hilavitkutin_extensions` when they need it), rename it (e.g. `HilaExtensionHost`), or fold both shapes into one type at the Resource layer. Decision deferred to Slice 8b because the call depends on how viola-cli composes the scheduler-builder's Resource registration against the FFI-side extension loading surface.
