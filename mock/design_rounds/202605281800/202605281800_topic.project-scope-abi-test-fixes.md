# Topic: strengthen project-scope ABI layout tests

**Date:** 2026-05-28 **Phase:** TOPIC **Scope:** Make the `IndexBatch` and
`LintEvaluateProjectIndexVtable` layout tests assert actual field offsets so
they catch reordering, not just total size. Source-only; touches
`viola-plugin-abi/src/lib.rs`.

**Source TOPIC:** round 202605281600 (project-scope ABI), on this branch.

# Why this round exists

A pre-merge review found the two layout tests added in round 202605281600 are
weak in the exact dimension they exist to guard.
`index_batch_layout_pointer_plus_three_usize` calls `offset_of!` four times but
binds each to `let _ =`, asserting nothing, then checks only total `size_of`.
Because the three `arvo::USize` fields are the same width, swapping `capacity` /
`len` / `needed`, or moving `entries` off the front, leaves the test green.
`project_index_vtable_is_two_words` similarly checks only total width, so
swapping the two differently-typed function pointers passes. For a `#[repr(C)]`
wire contract whose field order this PR is the artefact-of-record for, the tests
must pin the order.

# What lands

- `index_batch_layout_*`: assert each field's offset (`entries == 0`, then the
  three `USize` at successive offsets derived from `size_of`), pinning order and
  the no-padding layout portably across pointer widths.
- `project_index_vtable_*`: assert `index_phase` at offset 0 and
  `evaluate_phase` at one function-pointer width, pinning the two-slot order.
