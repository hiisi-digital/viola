## CHANGE: trait `EmitWriter` FROM `pub trait` TO `pub trait EmitWriter: Send + Sync`
File: `mock/crates/viola-core/src/wus/mod.rs`
Verification: `grep -q '^pub trait EmitWriter: Send + Sync' mock/crates/viola-core/src/wus/mod.rs`.

The bound on `pub trait EmitWriter` adds `Send + Sync` as supertraits. The `Sync` bound is load-bearing for the existing `unsafe impl<W: EmitWriter> Sync for DiagnosticSink<W>` in the same file: without `W: Send + Sync` the four-invariant Sync contract on the Resource cannot complete. Every existing concrete `EmitWriter` impl (`StderrEmitter` ZST, `EmitFlat` no-op) trivially satisfies `Send + Sync`; future LSP/network-buffered emitters either are `Send + Sync` by structural composition or take an internal `Mutex` to satisfy the bound.

## CHANGE: impl bound on `EmitDiagnostics<W>` FROM `W: EmitWriter + Send + Sync + 'static` TO `W: EmitWriter + 'static`
File: `mock/crates/viola-core/src/wus/emit_diagnostics.rs`
Verification: `grep -q 'impl<W: EmitWriter + .static> WorkUnit for EmitDiagnostics<W>' mock/crates/viola-core/src/wus/emit_diagnostics.rs`.

The explicit `Send + Sync` bound on the existing `impl WorkUnit for EmitDiagnostics<W>` is now redundant: it flows from the supertrait promotion in the previous CHANGE. Drop the redundant bound; the `'static` bound stays. Strictly mechanical simplification.

## CHANGE: viola-cli/src/main.rs ADDS recursion_limit raise + dead_code drop + register_lints macro + scheduler-build chain replacing unimplemented stub
File: `mock/crates/viola-cli/src/main.rs`
Verification: `grep -q '^#!\\[recursion_limit = "1024"\\]' mock/crates/viola-cli/src/main.rs && grep -q '^macro_rules! register_lints' mock/crates/viola-cli/src/main.rs && grep -q 'Scheduler::builder()' mock/crates/viola-cli/src/main.rs && ! grep -q 'unimplemented!.*Slice 8b ships' mock/crates/viola-cli/src/main.rs`.

Five sub-changes in one file:

1. `#![recursion_limit = "1024"]` added at top. Required for the deep cons-list `ContainsAll<L>` typestate proofs that the scheduler `.build()` call relies on; the default `recursion_limit = 128` overflows once the chain crosses around 25 registered builder-inputs, and the slice's chain registers around 50.

2. `mod emit;` declaration loses its `#[allow(dead_code)]` annotation (Slice 8b.1 added it; Slice 8b.2 consumes the module natively via the scheduler-build chain). The five forward-keepalive items in the file body (`EXIT_OK`, `EXIT_PLUGIN`, `HOST_CAPS_EMPTY`, `_BYTES_REF_KEEPALIVE`, `load_plugin`) similarly lose their `#[allow(dead_code)]` annotations to the extent Slice 8b.2 references them. Items that remain unused after 8b.2 keep the annotation; the discipline is consumer-driven, not blanket.

3. Imports added: `hilavitkutin::scheduler::Scheduler`, `hilavitkutin_api::store::{Column, Resource}`, `viola_core::resources::{CiState, DiagnosticCounts, DiscoveredFilePaths, ExtensionHost as HostExtensionHost, FileEntryBuffer, LintConfigBuffer, LintSlots, Workspace}`, `viola_core::wus::{DiagnosticSink, DiscoverFiles, EmitDiagnostics, FileInfo, LoadConfig, LoadPlugins, Nam, PluginEntry, RunLint, RunRunner, WuDiagnostic}`, `viola_config::{ConfigBytes, ViolaCfg}`, `viola_plugin_abi::RunSurface`, `crate::emit::StderrEmitter`.

4. Local `macro_rules! register_lints` added: unrolls 32 `.with(RunLint::<N>)` calls for N = 0..31. Rust declarative macros do not support count-driven loops natively; the unroll is the canonical workaround.

5. Unix-main body's `unimplemented!("Slice 8b ships viola-cli scheduler rewire ...")` stub replaced with the scheduler-build chain. The chain registers twelve Resources, four Columns, five unit-WU instances, plus the 32-instance RunLint cohort via the macro. Final calls: `.build()` then `.run()`. The unix-main function returns `EXIT_OK` after `.run()` returns. Runtime executes `.run()`'s `unimplemented!()` until the hilavitkutin runtime megaround Pass 7+8 lands; the AccessSet contracts compile at `.build()`, which is Slice 8b.2's lock criterion.
