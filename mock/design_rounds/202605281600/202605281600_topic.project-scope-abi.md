# Topic: two-phase project-scope lint ABI (LintEvaluateProjectIndexVtable + IndexBatch)

**Date:** 2026-05-28
**Phase:** TOPIC
**Scope:** Add the viola plugin ABI surface for project-scoped (cross-file) lints: a two-phase index-then-evaluate vtable, the shared `IndexBatch` carrier, and a distinct provider id. Touches `viola-plugin-abi` only (`src/vtable.rs`, `src/lib.rs`). No host dispatch in this slice.

**Source TOPIC:** mockspace `mock/research/202605260200_cdylib-port-decisions-locked.md` Decision 3 (Option ii), locked by op 2026-05-25.

# Why this round exists

Bucket-3 lints (`no_duplicate_fn`, `undocumented_type`) are cross-crate: they need a project-wide index before they can emit per-file findings. Decision 3 (Option ii) splits that into two vtable slots. `index_phase` runs once over the full NAM and builds a plugin-defined index into a host-owned `IndexBatch` buffer; `evaluate_phase` runs per file, reading the shared index and writing that file's findings into a host-owned output buffer. Splitting the work keeps overflow per-file (one busy file does not fill the whole project's buffer), lets the host parallelise `evaluate_phase` across files, and factors the index out as a natural cache key for future incremental linting.

# Why the host dispatch is not in this slice

The memo's slice-1 list names host-side dispatch helpers including a re-allocate-on-overflow loop. viola-core is `#![no_std]` + no_alloc and has no project-scoped host WorkUnit today (the lint host is `RunLint<L>`, per-file, single-phase). A re-allocating host loop conflicts with no_alloc, and the project-scoped WorkUnit that would own the `IndexBatch` allocation does not exist yet. So this slice ships the ABI surface the cdylibs (#619) compile against and the future host WorkUnit will dispatch through; the dispatch loop and allocation strategy land with that host work. This mirrors the NAM v1.1.0 slice (#616), which shipped the schema and deferred the host serialiser to the runner plugin.

# What lands (viola-plugin-abi only)

- `IndexBatch` `#[repr(C)]` carrier: `entries: *mut c_void` (opaque, host-allocated, plugin writes through), `capacity`, `len`, `needed` (all `arvo::USize`). The host never inspects `entries`; it shuttles the same pointer from `index_phase` output into every `evaluate_phase` call. On `index_phase` overflow the plugin returns `AbiStatus::Internal`, sets `len` to what it wrote, and writes the capacity it needs into `needed`. `capacity` / `len` / `needed` are in plugin-defined units.
- `MAX_INDEX_ENTRIES`: documented default `IndexBatch` capacity (`1 << 20`) a host pre-allocates, per the locked contract.
- `LintEvaluateProjectIndexVtable` `#[repr(C)]`: two function pointers, `index_phase(host_ctx, nam, lint_config_bytes, lint_config_len, out_index)` and `evaluate_phase(host_ctx, nam, file_idx, index, out_entries, out_capacity, out_len)`. `evaluate_phase`'s output buffer reuses the host-owned-buffer + overflow contract from `LintEvaluateVtable`.
- `PROVIDER_LINT_EVALUATE_PROJECT` const: `viola.lint.evaluate-project.v1`. A distinct provider id, not a vtable extension of the existing lint provider (the vtable shapes stay append-only).

# Open / deferred

- Host dispatch loop, `IndexBatch` allocation, re-allocate-on-overflow, per-file parallel `evaluate_phase`: land with the future project-scoped host WorkUnit.
- The internal layout the cdylib writes into `IndexBatch.entries` is plugin-defined and surfaces at the wave-5 first-port sketch (#619); the host treats it opaquely.
