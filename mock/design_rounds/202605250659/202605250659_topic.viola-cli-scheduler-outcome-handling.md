# Topic: viola-cli Scheduler::run Outcome handling

**Date:** 2026-05-25
**Phase:** TOPIC
**Scope:** viola-cli
**Source topics:** Closes the `viola-cli Scheduler::run Outcome handling` BACKLOG entry added during Slice 8b.2. Sequenced "after the engine body lands" per that entry; hilavitkutin engine body landed at `c040b4d` (PR #83); now actionable.

## Current state

Slice 8b.2 shipped the scheduler-build chain in viola-cli's unix-main ending with `let _ = scheduler.run(); EXIT_OK`. The `let _ =` discarded the `Outcome<(), ()>` because hilavitkutin's `Scheduler::run` was `unimplemented!()` and would panic before any return. PR #83 on hilavitkutin replaced that with a no-op body returning `Cfg::Out::default()` = `Outcome::Ok(())`. The Outcome is now a real return value carrying a real success/error signal.

This slice closes the BACKLOG entry I wrote in Slice 8b.2 saying: "the follow-up that wires the Outcome to a concrete exit code (`EXIT_OK` on `Ok`, `EXIT_PLUGIN` on `Err`) is tracked under viola-core's `viola-cli Scheduler::run Outcome handling` BACKLOG entry; reaching that point requires the engine body and the host-shim Resources to be populated".

## Changes proposed

### Source edit

`viola-cli/src/main.rs`: replace `let _ = scheduler.run(); EXIT_OK` with a `match` block:
- `notko::Outcome::Ok(_)` returns `EXIT_OK`.
- `notko::Outcome::Err(_)` returns `EXIT_PLUGIN`.

The wave-y comment block before the call updates to describe the now-shipped wiring instead of a deferral.

### Why both arms

`DefaultRunCfg::Out = Outcome<(), ()>`. Today the no-op body always returns `Ok(())` so the `Err` arm is unreachable in practice. The match arm exists for the future: once the real morsel loop body lands (the LLVM-plugin-gated follow-up), the engine can surface failures via the Err side, and viola-cli's exit code reflects that without further wiring. Pre-1.0 forward compatibility.

### BACKLOG update

Revise the `viola-cli Scheduler::run Outcome handling` entry in `viola-core/BACKLOG.md.tmpl` to mark "Shipped in this slice" per the BACKLOG convention.

### Out of scope

- Host-shim Resource population (real workspace path, real CI detection, real plugin handles, real config bytes from disk). The current scheduler-build chain uses defaults; that's the next layer of slice work.
- Real morsel-loop testing (panics at `hilavitkutin::Scheduler::run`'s real body — but that body now returns no-op-Ok cleanly, so this test path is the FIRST viable end-to-end runtime test for #254 at type AND runtime level).
