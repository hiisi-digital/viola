# Topic: NAM v1.1.0 schema (flat NamNode array + canonical Rust node-kind ids)

**Date:** 2026-05-28 **Phase:** TOPIC **Scope:** Extend the viola plugin ABI's
NAM surface to v1.1.0: a serialised flat AST node array carried per file, plus a
workspace-canonical Rust node-kind id table. Touches `viola-plugin-abi` only
(`src/nam.rs`, `src/lib.rs` re-exports + tests). No host serialiser in this
slice.

**Source TOPIC:** mockspace
`mock/research/202605260200_cdylib-port-decisions-locked.md` Decision 2 (Option
b), locked by op 2026-05-25.

# Why this round exists

The mockspace #610 lint-catalogue port reimplements each lint as a cdylib.
Bucket-2 lints (`no_todo` tree-sitter variant, `export_count`, `no_empty_crate`)
need the parsed AST, but cdylibs must not link tree-sitter. Decision 2 (Option
b) resolves this: the host pre-walks the tree-sitter tree once per parse and
serialises it into a flat `#[repr(C)]` node array exposed through NAM; cdylibs
walk the array by index arithmetic, with no tree-sitter dependency. The node
kinds are named by stable ids drawn from a workspace-canonical table so every
cdylib agrees on what id `7` means without sharing a grammar.

# Why the host serialiser is not in this slice

The memo's slice-1 list names a host serialiser that walks the tree-sitter tree
into the flat array. viola has no host-side tree-sitter wiring today: NAM is
produced by the runner plugin via the `execute_scope` FFI (`RunRunner` only
receives and stores the returned `NamPayload`), and the rust-native runner that
would parse and serialise is task #220, not yet built. So this slice ships the
ABI surface the serialiser and the cdylibs both compile against; the serialiser
lands with the runner plugin. The accessor and the node-kind table are the
contract both sides share.

# What lands (viola-plugin-abi only)

- `NamVersion::V1_1_0` const (`1, 1, 0`).
- `NamNode` `#[repr(C)]` struct: `kind`, `parent`, `first_child`, `start_byte`,
  `end_byte`, `start_row`, `end_row`, all `arvo::USize`. Tree topology is
  encoded by indices into the same slice; a `parent` or `first_child` equal to
  the slice length is the one-past-the-end sentinel (root has no parent, a leaf
  has no first child).
- `NamFileEntry` gains a `nodes: BytesRef` carrier (pointer + byte length)
  addressing the per-file `NamNode` array. The carrier is empty
  (`BytesRef::EMPTY`) for a file with no serialised tree (the v1.0.0 producer
  case).
- `nam_file_nodes<'a>(entry: &'a NamFileEntry) -> Option<&'a [NamNode]>`
  accessor: `None` when the carrier is null (no tree available), else the node
  slice (count = `nodes.len / size_of::<NamNode>()`).
- `nam_file_entries` version gate widens from exact `V1_0_0` to `major == 1`:
  the `NamFileEntry` layout is stable across the v1.x line (fields only
  appended; the appended `nodes` carrier is part of the shared struct), so any
  1.x payload walks with the same accessor.
- Canonical Rust node-kind id table in a `node_kind` module: `pub const`
  `arvo::USize` ids, `UNKNOWN = 0` plus the common Rust item, comment, and
  visibility kinds the bucket-2 consumers identify. Initial coverage is Rust;
  other grammars and id-table growth ship per later schema sub-versions.

# Deferred / open

- `NamNode.kind`'s exact arvo width: the memo defers the narrowing decision to
  the wave-4 first-port sketch (mockspace-side #617). This slice ships
  `arvo::USize` per the memo's starting shape; the cdylib sketch may propose a
  narrower width as a follow-up.
- Host serialiser: ships with the rust-native runner (#220).
