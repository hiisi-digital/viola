**Phase:** DOC (living until lock) **Topic:**

## What ships

The v1 lint vtable returned a plugin-owned `DiagnosticBatch` view; the host
copied entries before the next call, which serialised every invocation through
one static buffer. ABI v2 makes the host own the buffer: `evaluate` takes a
`*mut Diagnostic` slice with its capacity and an out-length pointer, the plugin
writes through, and the `DiagnosticBatch` carrier is deleted. The provider id
moves to `viola.lint.evaluate.v2`. Plugins become pure functions over their
inputs, which is what lets the host fan `RunLint<L>` out in parallel.

## CHANGE: `RunLint<L>` host call REWRITTEN to host-owned buffer

File: `viola/mock/crates/viola-core/src/wus/run_lint.rs`. The `DiagnosticBatch`
import is dropped and `Diagnostic` imported. The body allocates a fixed-capacity
`Diagnostic` buffer of `MAX_DIAGS_PER_LINT` slots, passes `out_entries` +
`out_capacity` + `&mut out_len` to `evaluate`, reads `out_len` for the written
count, and projects up to `MAX_DIAGS_PER_LINT` entries into the per-L row range.
`AbiStatus::Internal` (overflow) is treated as a non-fatal truncation: the host
projects the first `MAX_DIAGS_PER_LINT` entries and continues. The fixed-buffer
mechanism is `core::mem::MaybeUninit` (`Diagnostic` is `Copy` plain-old-data, no
`Drop`).

Verification: `grep "out_len" viola/mock/crates/viola-core/src/wus/run_lint.rs`
