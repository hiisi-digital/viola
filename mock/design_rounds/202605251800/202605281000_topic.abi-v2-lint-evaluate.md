# Topic: ABI v2 lint-evaluate vtable (host-owned buffer)

**Date:** 2026-05-28 **Phase:** TOPIC **Scope:** Change the lint role's
evaluation entrypoint from a plugin-owned diagnostic buffer to a host-owned one.
`LintEvaluateVtable.evaluate` takes `out_entries: *mut Diagnostic` +
`out_capacity` + `out_len` instead of `out_batch: *mut DiagnosticBatch`; the
`DiagnosticBatch` carrier is deleted; the provider id renames to
`viola.lint.evaluate.v2`. Touches `viola-plugin-abi`, `viola-core`,
`viola-test-plugin-fixture`, `viola-deno-runtime`. **Source TOPIC:** mockspace
`mock/research/202605260200_cdylib-port-decisions-locked.md` Decision 1 (Option
B), locked by op 2026-05-25.

# Why this round exists

The mockspace #610 lint-catalogue port reimplements each lint as a cdylib that
exports the `viola.lint.evaluate` vtable. The v1 vtable hands the host a
`DiagnosticBatch { entries: *const Diagnostic, len }` view into plugin-owned
memory, so the plugin must keep a static buffer alive and the host must copy out
before the next invocation. That shape caps host throughput at one serial call
per provider: the static buffer cannot be reused concurrently, so
`RunLint<0>..RunLint<31>` cannot share one provider in parallel.

Option B inverts ownership. The host allocates the output buffer and passes a
`*mut Diagnostic` slice plus its capacity; the plugin writes through and reports
how many entries it wrote (or would have written). The plugin becomes a pure
function over its inputs with no retained state, so the host can run many
invocations in parallel, each with its own buffer. This is the prerequisite for
the wave-1 cdylib port (no-todo) and every later port; it lands first because it
is the smallest change and unblocks waves 1, 2, and 3 at once.

# What lands

- `LintEvaluateVtable.evaluate` signature changes to the host-owned-buffer
  shape:
  `(host_ctx, nam, lint_config_bytes, lint_config_len, out_entries: *mut Diagnostic, out_capacity, out_len: *mut arvo::USize) -> AbiStatus`.
- `DiagnosticBatch` `#[repr(C)]` carrier and its `Send`/`Sync` impls are deleted
  from `diagnostic.rs`. No consumer references it outside the vtable, so per the
  no-legacy-shims-pre-1.0 rule v1 is deleted outright rather than aliased.
- `PROVIDER_LINT_EVALUATE` renames its wire value from `viola.lint.evaluate.v1`
  to `viola.lint.evaluate.v2`. The Rust constant name stays
  `PROVIDER_LINT_EVALUATE`.
- The host `RunLint<L>` WorkUnit (`viola-core`) is rewritten to provide a
  fixed-capacity stack buffer of `Diagnostic` (capacity `MAX_DIAGS_PER_LINT`),
  pass it to `evaluate`, read `out_len`, and project the written entries into
  the per-L row range of `Column<WuDiagnostic>`.
- The host-loader integration test, the test-plugin fixture, and the
  deno-runtime worker are migrated to the v2 shape.

# Overflow contract

The ABI is capacity-agnostic: the host passes whatever capacity its buffer has,
and the plugin must never write past `out_capacity`. On success the plugin
writes `n <= out_capacity` entries and sets `*out_len = n`, returning
`AbiStatus::Ok`. On overflow (the lint would emit more than `out_capacity`
entries) the plugin writes the first `out_capacity` entries, sets `*out_len` to
the count it would have emitted, and returns `AbiStatus::Internal`. The host
detects the overflow from the non-`Ok` status and the `*out_len > out_capacity`
signal, projects what fits, and records the truncation. viola's host buffer
capacity is `MAX_DIAGS_PER_LINT` (64); the 256 default named in the locked memo
is a mockspace-side cdylib policy, not an ABI constant.
