# Settling the EmitWriter return-type call

Slice 7a's CL named the unit-vs-`Outcome<()>` return-type call as an open
question for Slice 7b. Slice 7b settles as **unit-return**:

- `fn write_str(&mut self, s: &str)`
- `fn write_bytes(&mut self, bytes: &[u8])`
- `fn flush(&mut self)`

Rationale: the WU body has no useful recovery action on per-write failure. If
the egress writer fails mid-emit, the WU cannot retry, cannot back off, cannot
route to an alternate sink without a Resource-shape redesign. The right place to
handle write failure is inside viola-cli's concrete impl, where it has access to
syscall context and CLI policy (e.g. panic on stderr loss, fall back to stdout,
log and continue). The WU body remains a pure data-projection over the column.

The trade is observability lost vs callsite simplicity gained. Pre-1.0; the
trait can flip to `Outcome<()>` later when a real use-case (LSP-buffered emit,
network-shaped sink) surfaces a recovery action.

# DiagnosticCounts shape: no shared counter

The Slice 7a topic had named a `populated` counter sibling field on
`DiagnosticCounts` as a cheap O(1) "any diagnostics?" check for the
EmitDiagnostics short-circuit. **Slice 7b drops the shared counter.** Reason:
the parallel RunLint cohort writes `counts[L]` at distinct L (disjoint slot
indexes; commutative under the COMMUTATIVE flag), but a sibling `populated`
counter is a shared scalar; a non-atomic read-modify-write
(`let prev = ...get(); set(prev + 1)`) on `Cell<USize>` from N parallel writers
is a data race under the cohort's parallel dispatch, regardless of end-state
commutativity intent.

Two paths avoid the race:

1. **Drop the counter, scan on read.** EmitDiagnostics scans
   `counts[0..MAX_LINTS]` (32 entries) once at the start of execute. Trivial
   cost; lives entirely on the read side; no shared mutable state.
2. **Use `AtomicUsize` for the counter.** Adds an atomic increment per RunLint
   dispatch path; atomic ordering needs to be Relaxed (commutativity holds for
   counts), but cross-platform Atomic is `core::sync::atomic::AtomicUsize` which
   couples viola-core to the std-side atomic surface.

Slice 7b picks **Path 1**. The 32-entry scan is cheap, lives on the read side
which is already O(MAX_LINTS) for the per-L iteration loop, and avoids
introducing atomic ordering reasoning into the Resource contract. Future Slice 9
audit may revisit if the scan cost becomes visible in dispatch benchmarks.

# What lands in source

In `viola-core/src/wus/mod.rs` (or a new `viola-core/src/emit.rs` to keep the
WU-stub module focused; Slice 7b picks the layout per the existing pattern of
types alongside their WU):

- `pub trait EmitWriter { fn write_str(&mut self, s: &str); fn write_bytes(&mut self, bytes: &[u8]); fn flush(&mut self); }`.
  Marker `'static` bound omitted from the trait body; consumers compose with
  `'static` at the Resource registration site. The trait itself stays minimal.
- `DiagnosticSink` flips from the Slice 7a non-ZST placeholder to
  `pub struct DiagnosticSink<W: EmitWriter> { writer: UnsafeCell<W> }` with
  private `writer` field.
  `unsafe impl<W: EmitWriter> Sync for DiagnosticSink<W>` carries the
  four-invariant SAFETY contract paralleling host-shim Resources, but
  **EmitDiagnostics is the sole writer** declared in its `Write` set rather than
  the host shim. The contract: EmitDiagnostics is the only WU writing this
  Resource (declared in Write); the scheduler serialises Write access; no other
  WU declares this Resource anywhere; the interior mutability through `&self` is
  single-threaded per the scheduler's per-WU dispatch model.
- `pub fn new(writer: W) -> Self` constructor for viola-cli to register the
  Resource with its concrete impl. No `Default` impl because `EmitWriter` itself
  doesn't bound `Default`.
- The `staged` placeholder field from Slice 7a is removed (the Slice 7a flip's
  only purpose was bridging the ZST-to-generic gap; the placeholder field never
  had a stable semantic).
- `pub struct EmitFlat;` ZST + no-op `EmitWriter` impl. Lets witness tests
  instantiate `EmitDiagnostics<EmitFlat>` and `DiagnosticSink<EmitFlat>` without
  pulling viola-cli's concrete impl into the test build.

In `viola-core/src/resources.rs`:

- `pub struct DiagnosticCounts { counts: UnsafeCell<[arvo::USize; MAX_LINTS]> }`.
  Single field. Same four-invariant `unsafe impl Sync` pattern, but **RunLint<L>
  is the writer**: each L writes `counts[L] = its_per_L_count`. EmitDiagnostics
  reads to bound the per-L iteration. Distinct from the host-shim-populated
  Resources (which had host shim as sole writer at builder time);
  DiagnosticCounts is written at WU dispatch time by the parallel RunLint
  cohort.
- `pub unsafe fn set_count(&self, slot: arvo::Cap, count: arvo::USize)`. The
  `# Safety` clause names: per-L writes at distinct slot indexes for distinct L
  commute trivially (disjoint slot indexes); the RunLint cohort's parallel
  writes to distinct slots are safe under the COMMUTATIVE flag. **No shared
  counter** is touched; the disjoint-slot strategy is the only synchronisation.
- `pub fn count_at(&self, slot: arvo::Cap) -> arvo::USize` safe read accessor
  for EmitDiagnostics.
- `pub fn any_populated(&self) -> arvo::Bool` safe read accessor. Walks
  `counts[0..MAX_LINTS]` once; returns Bool::TRUE if any slot is non-zero. The
  32-entry scan is the alternative to the dropped shared counter; lives on the
  read side; phase-separation guarantees no concurrent writer at scan time.

In `viola-core/src/wus/run_lint.rs`:

- AccessSet Write extends from `Cons<Column<WuDiagnostic>, Empty>` to
  `Cons<Column<WuDiagnostic>, Cons<Resource<DiagnosticCounts>, Empty>>`. **This
  is a load-bearing AccessSet change to the previously-closed Slice 6b RunLint
  WU body.** Pre-1.0; the edit lands inside this round's scope per the Slice 7a
  CL's documented framing.
- Body edit: after the projection loop (and at every other exit point), write
  `DiagnosticCounts::set_count(arvo::Cap(USize(L)), USize(count))`. One line
  plus the safety reasoning per exit.
- Body's `emit_failure::<L>` path writes one record, so the failure path's per-L
  count is 1; the empty-slot path's count is 0; the body picks the cleanest
  approach.

In `viola-core/src/wus/emit_diagnostics.rs`:

- `EmitDiagnostics<W: EmitWriter>` becomes generic. AccessSet:

```
Read = Cons<Resource<DiagnosticCounts>, Cons<Column<WuDiagnostic>, Empty>>
Write = Cons<Resource<DiagnosticSink<W>>, Empty>
```

- Body: short-circuits when `counts.any_populated().as_bool() == false`, after
  flushing the sink. Otherwise walks slots L in [0, MAX_LINTS) reading
  `DiagnosticCounts::count_at(L)`. For each L with count > 0, walks slots
  `[L * MAX_DIAGS_PER_LINT, L * MAX_DIAGS_PER_LINT + count)` reading each
  WuDiagnostic record. Stages all read records into a stack-cap-bounded array
  (size = `MAX_LINTS * MAX_DIAGS_PER_LINT`). Sorts via the host-side
  approximation comparator (with `original_slot_index` tiebreaker). Walks the
  sorted array, formats each diagnostic as a single human-readable line, calls
  `EmitWriter::write_str` on the format. Calls `flush` at the end.
- The stack-cap array is the per-call working buffer.
  `MAX_LINTS * MAX_DIAGS_PER_LINT = 32 * 64 = 2048`; each `StagedRecord` is
  approximately 64 to 80 bytes (WuDiagnostic plus a `original_slot_index: USize`
  tracker); total around 130 to 160 KB on the stack. Pre-1.0; revisable to a
  transient Resource if stack pressure surfaces. A static_assertions guard pins
  the array size against MAX_LINTS * MAX_DIAGS_PER_LINT at compile time so the
  buffer cap cannot drift silently if those caps revise upward.
- The stage-prefix sort uses **insertion sort** (stable, simple,
  no_std-friendly, dominated by per-record emit cost for typical N). Stability
  is theoretically redundant because the `original_slot_index` tiebreaker makes
  the comparator total, but stability + total comparator is the safer pair than
  non-stable + total comparator (the comment + BACKLOG entry stop relying on
  stability as load-bearing once the tiebreaker proves comparator totality).

# Slice 9 audit precondition

The RunLint AccessSet Write extension adds `Resource<DiagnosticCounts>` to the
parallel-fan-out cohort. The COMMUTATIVE flag's claim depends on RunLint<L>
writes for distinct L touching disjoint memory. Per-L writes to
`DiagnosticCounts[L]` touch distinct slot indexes by construction; commutativity
holds. With no shared `populated` counter, there is no shared mutable scalar to
reason about. Slice 9 audits this as part of its existing scope; the explicit
BACKLOG entry from Slice 7a already names this precondition.
