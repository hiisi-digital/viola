# Why this round exists

The mockspace bucket-3 cdylib lints walk the NAM flat `NamNode` array to reason
about names across files. The no-duplicate-fn lint reads the name token of a
function item to detect duplicate definitions. That name token is a plain
identifier leaf, distinct from `TYPE_IDENTIFIER` (which names a type). The
current table has no kind for it, so a cdylib cannot tell a name-token leaf from
any other unknown leaf.

`IDENTIFIER` names that leaf: the name token of an item, function, field,
variant, or binding. A lint reads the name by taking the node's source byte
span. This kind also belongs in the producer's vocabulary (the rust-native
runner, #220), so defining it now is foundational, like #616 / #617 shipping
schema ahead of the producer.
