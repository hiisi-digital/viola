Open the first round of viola #254 implementation. Slice 1 per the scoping memo: create `viola-core/src/resources.rs` defining `Workspace`, `CiState`, `RunSurface` POD value types, plus a `viola-core/src/wus/` module tree with empty stub `WorkUnit` impls. `ViolaConfig` lives in the separate `viola-config` crate (per HILAVITKUTIN-APP-SHAPE.md line 149) and gets re-exported through `viola-core` rather than redefined here.

## What lands in this slice

Resource value types in `viola-core/src/resources.rs`:

- `Workspace`: workspace root path + run-mode classification. Stack-cap fields, no heap.
- `CiState`: CI environment flag + agent classification. Bool plus enum variant.
- `RunSurface`: surface kind discriminator (CLI / LSP / DAP / hook).

WorkUnit stubs in `viola-core/src/wus/` (one file per unit, `pub use` re-exported through `wus::mod.rs`):

- `LoadConfig`, `LoadPlugins`, `DiscoverFiles`, `RunRunner`, `RunLint<L>`, `EmitDiagnostics`.

Each stub:

- Declares `type Read: AccessSet` and `type Write: AccessSet` from `hilavitkutin-api`.
- Declares `type Hint: SchedulingHint` per the relevant axes.
- Declares `type Ctx<'frame>` with the seven required accessor bounds.
- Body: `unimplemented!("slice N implements this")` with the slice number from the scoping memo.
- Pairs with `impl BuilderInput for X { type Init = Self; type Dispatch = UnitDispatch<Self>; }` per the trait's `on_unimplemented` directive.

Module wiring:

- `viola-core/src/lib.rs` adds `pub mod resources;` and `pub mod wus;`.
- `wus/mod.rs` re-exports each unit type at the `wus::` path.
