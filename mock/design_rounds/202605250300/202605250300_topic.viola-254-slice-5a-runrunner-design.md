# Design tensions for the RunRunner body

The body lifts to FFI via
`viola_plugin_abi::RunnerExecuteScopeVtable::execute_scope`. The call shape is
`unsafe extern "C" fn(host_ctx: *mut c_void, scope: *const RunScope, out_nam: *mut NamPayload) -> AbiStatus`.
The runner is scope-shaped: one call receives the entire `RunScope` covering
every file in the run, returns one `NamPayload` carrying the scope-wide NAM. The
body marshals Resources into `RunScope` at the FFI call site.

## Tension 1: `Column<Nam>` versus `Resource<Nam>`

The runner returns ONE NAM per scope. The Slice 1 AccessSet declared
`Write = Cons<Column<Nam>, Empty>`. A column with exactly one row is
mechanically fine, but the semantic shape is singleton.

This round picks `Column<Nam>` per the Slice 1 declaration. Rationale: the
column form keeps the door open for future per-file incremental runners that
produce a `Nam` per file. The body writes ONE row to slot zero for the
scope-wide NAM. The singleton-row convention is documented.

If a future design decides per-file runners are forbidden by the ABI, the
AccessSet flips to `Write = Cons<Resource<Nam>, Empty>` then. The BACKLOG entry
tracks this.

## Tension 2: where does the `FileEntry` array live

`RunScope.files: *const FileEntry` and `RunScope.files_len: arvo::USize`. The
runner reads through the pointer; the host owns the memory for the duration of
the call. The array needs a stable home.

Options:

- **Path A: Host-shim-populated `Resource<FileEntryBuffer>`** paralleling
  `Resource<DiscoveredFilePaths>`. The host shim populates both at
  scheduler-builder time. RunRunner reads `Resource<FileEntryBuffer>`, builds
  `RunScope` on stack pointing into the buffer.
- **Path B: WU-built buffer in a transient Resource**. RunRunner has Write
  access to a buffer Resource, builds the entries on-the-fly from
  `Column<FileInfo>`, then calls FFI.
- **Path C: Reuse `Column<FileInfo>`'s underlying storage**. Requires `FileInfo`
  to be `#[repr(C)]` with the same layout as `FileEntry`. Slice 4's
  `FileInfo { path: Str, kind: FileKind }` and ABI
  `FileEntry { path: BytesRef, language: BytesRef, hash: BytesRef, size_bytes: u64 }`
  are layout-incompatible.

Slice 5b will pick Path A: host shim is the only place with filesystem access,
and FileEntry's fields (language detection, hash computation, size_bytes from
stat) all happen at filesystem walk time. The buffer mirrors
`DiscoveredFilePaths`: `UnsafeCell<[FileEntry; MAX_DISCOVERED_FILES]>` +
`Cell<arvo::USize>`. BACKLOG entry tracks the implementation.

## Tension 3: `FileEntry` enrichment beyond path

The ABI `FileEntry` needs `path`, `language`, `hash`, `size_bytes`. The host
shim today only knows paths (Slice 4's `DiscoveredFilePaths` carries `Str`
handles for paths only). Enrichment requires:

- **Language detection**: extension-driven or content-sniff. Slice 5b ships
  either an empty `language: BytesRef::EMPTY` (the plugin tolerates) or a simple
  extension-to-language map. BACKLOG entry.
- **Hash computation**: SHA-256 per ABI doc §9.3. Requires reading file contents
  at scheduler-builder time. Adds significant work to the host shim. BACKLOG
  entry tracks; initial Slice 5b ships empty hash.
- **size_bytes**: from filesystem stat at walk time. Easy to add to the host
  shim alongside path discovery. BACKLOG entry; initial Slice 5b ships zero.

## Tension 4: runner plugin resolution

Slice 5b body needs the runner plugin's `RunnerExecuteScopeVtable`. Resolution
path:

1. Walk `Column<PluginEntry>` finding one with the runner-role bit set
   (`PROVIDER_RUNNER_EXECUTE_SCOPE` becomes bit 0 per Slice 3's
   `resolve_descriptor`).
2. Use that entry's `host_idx` to get `&Library` via
   `ExtensionHost::library_at`.
3. Resolve the descriptor symbol from the library.
4. Walk the descriptor's provider table to find
   `PROVIDER_RUNNER_EXECUTE_SCOPE`'s vtable pointer.

The existing `viola_core::invoke::runner_vtable` helper takes a pre-#254
`Extension` type; Slice 5b cannot reuse it directly. Either lifts the helper to
operate on `&Library` directly, or inlines the descriptor walk. BACKLOG entry
tracks; recommended approach: a new helper
`viola_core::invoke::runner_vtable_from_library(&Library) -> Maybe<&'static RunnerExecuteScopeVtable>`.

## Tension 5: `host_ctx` model

The FFI signature passes `host_ctx: *mut c_void` opaquely. Plugins use it for
callbacks back into the host (logging, IPC, etc.). The cdylib boundary memo
Shape D specifies a contract for this; viola-core has no `host_ctx` resource
today.

Slice 5b ships `host_ctx = core::ptr::null_mut()`. Plugins must tolerate null
(the ABI doc names this case). When viola gains real callbacks (Slice 8
host-shim wire-up plus a callback-Resource follow-up), the `host_ctx` model
lands. BACKLOG entry tracks.

## Tension 6: `RunScope.workspace_root` and `RunScope.surface`

- `workspace_root: BytesRef` is a path-bytes pointer.
  `Resource<Workspace>.path: Str` is an interned handle. Resolving Str to raw
  bytes needs the host-shim long-lived interner (Slice 2b BACKLOG entry). Slice
  5b ships `BytesRef::EMPTY` until that lands.
- `surface: RunSurface` enum (Cli, Lsp, etc.). The host shim picks at
  scheduler-builder time. `Resource<CiState>` carries `is_ci` but not `surface`.
  Slice 5b either reads from a new `Resource<RunSurface>` (host shim populates)
  or hardcodes `RunSurface::Cli`. BACKLOG entry.

## Tension 7: `WuDiagnostic` write on failure

When the FFI call fails (AbiStatus != Ok, descriptor missing, library_at
out-of-bounds), Slice 5b emits a
`WuDiagnostic { source: WuDiagnosticSource::RunRunner }`. AccessSet extends
`Write` to include `Column<WuDiagnostic>`. This is straightforward; no design
tension.

# What lands in Slice 5a (this round)

- `Nam` flips from Slice 1 ZST to a fields-bearing carrier:
  `pub struct Nam { pub payload: viola_plugin_abi::NamPayload }`. Derives
  `Copy, Clone`. Cannot derive `Debug` because `NamPayload` does not derive
  `Debug` upstream (the `*const c_void` field is the blocker). SHAME entry
  tracks the Debug omission per `cl-claim-sketch-discipline.md`.
- `viola-core/DESIGN.md.tmpl` gets a `## Slice 5a NAM carrier` section
  documenting `Nam`'s host-side shape, the host-owned-memory contract for the
  inner `NamPayload`, and the singleton-row convention on `Column<Nam>`.
- `viola-core/BACKLOG.md.tmpl` gets seven new entries for the Slice 5b body
  deferrals (FileEntryBuffer Resource plus the six tensions named above).
- The `RunRunner::execute` body stays `unimplemented!()`. AccessSet stays
  exactly as Slice 1 declared. Slice 5b lands the body plus AccessSet refinement
  plus supporting Resources together.
