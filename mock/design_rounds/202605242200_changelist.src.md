## CHANGE: `ConfigArena<N>::arena_intern` and `arena_resolve` implementations shipped
File: `mock/crates/viola-config/src/lib.rs`
Verification: `! grep -q "Slice 2b implements ConfigArena::arena_intern" mock/crates/viola-config/src/lib.rs`.

`arena_intern` writes the input bytes to the buffer at the current cursor offset; appends a `(offset, length)` entry to the offsets table; advances cursor and entries_len; returns the entry index as the 28-bit id. `arena_resolve` reads the offsets table at the given id, returns a `&str` view of `bytes[offset..offset + length]`. Both methods use `unsafe` to access `UnsafeCell` contents.

## CHANGE: `unsafe impl Sync for ConfigArena` NEW
File: `mock/crates/viola-config/src/lib.rs`
Verification: `grep -q "unsafe impl<const N: usize> Sync for ConfigArena<N>" mock/crates/viola-config/src/lib.rs`.

SAFETY note states: `LoadConfig` is the sole producer (declared in its `Write` set; the scheduler's AccessSet contract serialises writes on a Resource); subsequent WUs hold `Read` access only and do not call `arena_intern`. The interior-mutability mechanism routes through the WU body's `&T` read borrow on `Resource<ViolaCfg>`; the borrow is single-threaded for the duration of the `execute` call per the scheduler's per-WU dispatch model. The `unsafe impl Sync` is sound under both the AccessSet serialisation guarantee and the single-threaded-per-dispatch invariant.

## CHANGE: `LoadConfig::execute` body shipped
File: `mock/crates/viola-core/src/wus/load_config.rs`
Verification: `! grep -q "Slice 2b implements LoadConfig" mock/crates/viola-core/src/wus/load_config.rs`.

Body reads `Resource<ConfigBytes>` via `ResourceProviderApi::resource()` (the canonical `&T` borrow accessor at `hilavitkutin-api/src/context.rs:64`). Calls `viola_config::parse::<MAX_PLUGINS>` on the slice. On `Outcome::Just`, projects the borrowed result into the existing `Resource<ViolaCfg>` via the `ViolaCfg::populate_from_borrowed(&self, borrowed)` method introduced alongside the body. The populate method takes `&self` because `ViolaCfg` carries interior mutability already (the bundled `ConfigArena` uses `Cell`/`UnsafeCell` for cursor and buffer per the DOC CL); writes route through the existing read borrow without a separate write accessor. This avoids introducing a hilavitkutin-api Resource-write surface in the same round.

On `Outcome::Aint`, constructs a `WuDiagnostic` with `source: ConfigParse`, severity `Error`, message interned from the parser's error formatter, range `Maybe::Isnt`. Writes to `Column<WuDiagnostic>` via `ColumnWriterApi::write(&self, i: USize, v: T)` at `hilavitkutin-api/src/context.rs:75`. The write index is the column's current length (one record appended); the source body queries the length via the column reader and writes at index `len`. The DOC CL's "appends" language reads as conceptual; the actual mechanism is index-based per the trait shape.

Both paths use `&T`-borrow surfaces only; the `unsafe impl Sync for ConfigArena<N>` SAFETY note holds because the WU body never escapes the `&self` borrow of either resource.

## CHANGE: file `viola-core/tests/load_config.rs` NEW
File: `mock/crates/viola-core/tests/load_config.rs`
Verification: `test -f mock/crates/viola-core/tests/load_config.rs`.

Three test functions:

- `access_set_shape_compiles`: type-level assertion that `<LoadConfig as WorkUnit>::Read` is `Cons<Resource<Workspace>, Cons<Resource<RunSurface>, Cons<Resource<ConfigBytes>, Empty>>>` and `Write` is `Cons<Resource<ViolaCfg>, Cons<Column<WuDiagnostic>, Empty>>`. Mechanism: a private `fn _assert_read<T>() where T: ReadIs<Cons<...>> {}` style witness pattern with a sealed `ReadIs<X>` trait implemented only for the matching type, so calling `_assert_read::<<LoadConfig as WorkUnit>::Read>()` fails to compile if the type does not match. The witness pattern beats `const _: () = { ... }` projections because it does not require a `PhantomData<T1>` to `PhantomData<T2>` coercion machinery that the workspace does not otherwise ship. The body PR commits the exact witness trait name.
- `parse_success_writes_violacfg`: builds a small `ConfigBytes` fixture with valid TOML, runs the WU body, asserts `Resource<ViolaCfg>` post-state. Uses the Slice 1 `WuCtxStub` Ctx surface (the test runs without the real engine Ctx).
- `parse_failure_writes_diagnostic`: builds a `ConfigBytes` fixture with malformed TOML, runs the WU body, asserts `Column<WuDiagnostic>` gained one record with `source: WuDiagnosticSource::ConfigParse`.
